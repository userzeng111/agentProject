嵌入式调试标签

直接在每个任务工作台里新增“调试”页签，复用当前任务上下文和 SSE。

优点

  • 实现最轻
  • 用户不迷路
  • 适合首批上线

代价

  • 跨任务对比弱
  • 后续平台化空间较窄

全局诊断页面

新增独立入口，例如 `/debug`，以任务为列表，以异常和性能为筛选维度。

优点

  • 跨任务排障强
  • 适合后续队列和状态机
  • 平台感更明确

代价

  • 首批数据聚合更重
  • 需要新导航和列表状态

推荐：摘要 + 详情

工作台显示当前任务的调试摘要；独立页面承载完整时间线、Agent 调用、LLM/RAG/SSE 诊断。

优点

  • 首批可控
  • 后续能扩展全局能力
  • 不挤压工作台主流程

代价

  • 需要定义摘要和详情两级契约

首批建议展示的信息

1

执行时间线

任务阶段、节点、Agent 调用、失败点、恢复动作按时间排列。

2

Agent 调用明细

角色、模型、输入摘要、输出摘要、分数、问题、耗时。

3

LLM / RAG 诊断

模型、token、缓存、RAG 命中、上下文预算、截断与重试。

4

失败与恢复建议

失败原因分类、可执行动作、推荐恢复路径、风险说明。
