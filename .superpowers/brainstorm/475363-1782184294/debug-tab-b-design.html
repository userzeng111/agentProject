首批设计：工作台内嵌“调试”标签页（B 方案）

定位：只读诊断投影层。先帮用户判断任务是否正常、卡在哪里、慢在哪里、能否恢复；不改变任务状态，不触发重跑。

工作台 Tab：调试
运行概览 | 章节进度 | 事件流 | Supervisor | 调试
1. 诊断结论
结论：运行正常 / 等待用户 / 可恢复异常 / 终态 / 状态不一致
判断依据：状态、最近事件、恢复契约、LLM/RAG 错误、SSE 连接状态
下一步：跳审核页 / 打开恢复弹窗 / 手动刷新 / 查看证据
2. 实时连接
SSE：连接中 / 已连接 / 正常终止 / 重连中 / 失败
最近事件：snapshot / task.event / task.done / keep-alive
重连次数与候选路径
3. LLM 诊断
请求次数、token、最慢阶段、首 token、cache hit、retry/repair、parse failed
4. Agent Trace
子 Agent 成败、评分、问题数、综合裁决、最近一轮摘要
5. 上下文 / RAG
上下文预算、压缩、响应缓存、RAG ready、检索错误、注入状态
6. 状态对账
TaskRecord 状态
pending_review 类型
novel_progress 阶段
supervisor 子任务摘要
checkpoint/恢复契约证据
7. 最近事件 + 证据链接
最近 20 条关键事件，按 stage/type 标注
refs：request.json、trace/current.json、context history、artifact index
原始内容只提供引用，不默认展开

首批数据流

1

主数据源：`getWorkspace(taskId)`

复用已有 `WorkspaceResponse`：meta、recent_events、llm_report、trace、context、cache、supervisor、agent_runs。

2

实时刷新：复用工作台 SSE

监听 snapshot / task.event / task.done，更新调试页摘要。SSE 失败时降级到手动刷新。

3

前端派生诊断

首批不强行新增后端 debug API，先用纯函数派生诊断结论、状态对账、LLM/RAG 摘要。
