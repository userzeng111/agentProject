## 只读核对结论

- `ProjectPageClient` 只在 `projectId` 变化时读取 workspace；审核完成或归档后仅切换同项目 `view`，父级继续使用旧 `meta`。
- `WorkspaceActionBar` 会打开归档确认框，但没有 `onArchive` 与 archive 分派；后端 `POST /api/tasks/{task_id}/archive` 和前端 `archiveTask()` 已存在。
- 动作矩阵硬编码禁用 `cancelled` 恢复，且 `CANCELLABLE_STATUSES` 漏掉 `waiting_manual_action`；后端已明确支持两项能力并已有测试。
- 聊天拆分丢失“点击当前会话直接返回”的保护；流式期间旧存档会覆盖内存中新消息。
- `npm run lint -- --no-cache` 实测为 31 个错误、14 个警告：29 个错误和全部警告来自聊天拆分，另 2 个错误来自新增 E2E 的未用变量/导入。
- project ID 初始态和无效态都被写成 `null`，导致无效地址页不可达。
- API 客户端丢弃 HTTP 状态，与既有设计中 `ApiRequestError` 的约束不符，因此 404 被误报为普通读取失败。
- Agent 行外层原生按钮内仍包含 `IconButton`，构成嵌套按钮。

## 已执行方案

1. 项目页按规范化后的 `view` 变化重新读取 workspace；保留空字符串作为无效 ID，`null` 只表示尚未解析。
2. 按既有设计新增 `ApiRequestError`，保留 `status/path/requestId/detail/retryable`；项目页单独渲染 404 不存在状态。
3. 工作台动作条新增 `onArchive`，任务工作台调用 archive API，成功后进入同项目归档视图，失败时留在原页提示。
4. 恢复 `cancelled` 的恢复动作，并把 `waiting_manual_action` 加回可取消状态集合。
5. 恢复聊天当前会话短路和展开态清理；新增延迟 SSE 回归，验证流式消息和 localStorage 均不损坏。
6. 将 Agent 行内箭头改为非交互装饰图标，保持外层按钮的唯一交互语义和键盘焦点。
7. 清理 31 个 lint 错误，并同步补齐拆分引入的 Hook 依赖，使 14 个警告也清零。
8. 新增/调整 API 单测、动作矩阵单测及 Playwright 用例，覆盖真实 `runs -> archive`、工作台归档、无效 ID、404、取消恢复、人工态取消、聊天流与嵌套按钮。
