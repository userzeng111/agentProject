# 日志模块整合：统一 agent-runtime 日志使用方式

## 用户原始诉求
统一 `/home/user01/WorkSpace/AgentProject/apps/agent-runtime/` 下所有 Python 文件的日志使用方式，将 `OLD/logger.py` 的文件轮转能力合并到 `app/observability/logger.py` 中，并全局替换标准 logging 导入。

## 当前状况
1. `app/observability/logger.py` 提供了结构化日志（带 request_id / task_id），但只有控制台输出。
2. 有 **23 个文件**使用 `logger = logging.getLogger(__name__)`。
3. `OLD/logger.py` 目录不存在，但需求描述中说明其提供：文件输出（DEBUG 级别，按天轮转，保留7天）。

## 目标
合并两者能力：保留 request_id/task_id 结构化追踪 + 增加文件按天轮转。

## 实施方案

### 1. 修改 `app/observability/logger.py`
- 在 `_StructuredFormatter` 中保留 request_id / task_id 字段
- 增加 `TimedRotatingFileHandler`（DEBUG 级别，按天轮转，保留7天）
- 日志目录：`/home/user01/WorkSpace/AgentProject/apps/agent-runtime/logs/`
- 控制台 handler 保持 INFO 级别
- 保留 `get_logger(name)` 函数签名不变
- 增加 `init_logging()` 函数供 main.py 调用
- 配置 uvicorn 日志器
- 导出：`get_logger(name: str) -> logging.Logger`、`init_logging()`、`request_id_var`, `task_id_var`

### 2. 全局替换 23 个 Python 文件
将 `import logging` + `logger = logging.getLogger(__name__)` 替换为 `from app.observability import get_logger` + `logger = get_logger(__name__)`。

不修改测试文件、不修改 `app/observability/logger.py` 自己的 import。

### 3. 修改 `app/main.py`
在 `app = FastAPI(...)` 之前添加 `init_logging()` 调用。

### 4. 更新 `app/observability/__init__.py`
导出 `init_logging`。
