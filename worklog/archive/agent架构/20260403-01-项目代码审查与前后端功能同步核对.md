## 当前评审结论

### 总体判断
- 当前仓库的主链路能力已经具备：创建任务、运行、三类审核、结果页、自动归档、归档列表与归档详情都已有实现。
- 但“前后端页面功能是否同步”只能判定为**部分同步**，主要问题不在于完全没有页面，而在于：
  - 前端页面已展示，但后端字段没有完整兑现；
  - 后端接口已支持，但前端入口/错误态/动作覆盖不完整；
  - 共享协议包已明显落后于真实接口，联调一致性主要靠人工维护。

### 关键问题分级

#### P0 / 严重
- 前端默认 API 地址与 README 启动说明不一致：
  - 前端默认走 `http://127.0.0.1:8000`
  - README 后端启动为 `http://127.0.0.1:8001`
  - 结果是开箱即用场景下前端会直接连错端口。
- 前端多个详情页存在“错误时假加载”问题：
  - `/tasks/[id]`
  - `/review/[id]`
  - `/result/[id]`
  - `/archive/[id]`
  - 首次请求失败时只记录错误，不会真正渲染错误态，用户会一直看到“正在读取”。
- 后端暴露了任务级 `auto_review` 字段，但实际执行并未按任务粒度生效：
  - `POST /api/tasks` 可提交 `auto_review`
  - `TaskRecord` 也有 `auto_review`
  - 但创建任务时未写入该字段，运行时实际使用的是服务级全局配置。
- 后端状态/流程语义里存在死分支：
  - `cancelled`
  - `waiting_manual_action`
  - `assembling`
  - 枚举、dashboard 与 SSE 仍暴露这些状态，但主图当前不可达。

#### P1 / 高
- 工作台页只给 `waiting_outline_review` 显示“进入审核”，没有覆盖：
  - `waiting_chapter_review`
  - `waiting_verification_review`
  - 导致从任务页继续走章节审核/验证审核时入口缺失。
- 共享协议包 `packages/shared-schema` 已明显过期：
  - `TaskStatus` 只剩极小子集
  - review/result/archive/workspace 等核心协议完全没有被共享包约束
  - 目前真实协议分别维护在前端本地类型与后端模型里。
- 大纲审核轮次 `revision_count` 在工作流中存在，但没有从后端 review 接口透出给前端，审核页只能通过类型断言猜测轮次。
- `/api/tasks/{id}/review` 在没有 `pending_review` 但已有历史审核时，会统一伪装成 `outline_review`，会误导前端对最后审核节点类型的判断。

#### P2 / 中
- `archive list` 前端类型声明了 `entry_refs`，但 API 实际不返回。
- `artifact_index.json_ref` 在前端类型中存在，但结果/归档接口实际不会返回。
- `archive detail` 前端类型与后端真实响应不一致：
  - 前端多声明了 `context_status/context_snapshot`
  - 后端实际返回了 `sources`
- 工作台上下文状态与后端真实落盘不完全一致：
  - 前端会消费 drafting 阶段上下文状态
  - 但后端当前主要只稳定持久化了 planning 快照。
- 首页“待处理”语义和后端 continue 列表不完全一致，后端把 `cancelled` 也放进了 continue 区。

#### P3 / 低
- 工作台页同时尝试 4 个 SSE 路径，说明事件流接口契约仍不稳定。
- 结果页与归档详情页虽然展示了 `md_ref/json_ref`，但没有提供直接点击查看或展开能力。
- 前端 lint 脚本当前不可直接用于校验：执行 `npm --prefix apps/web run lint` 会进入交互式初始化，而不是直接跑检查。
