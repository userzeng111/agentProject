# 问题标题
Agent 审核追踪动态派发语义修正

# 用户原始诉求
- Agent 审核追踪中显示派发了 `23` 个 Agent。
- 实际语义应为：主 Agent 动态派生 subagent 协同工作。
- 动态大纲需要保证各子 Agent 功能不重合。
- 只有主 Agent 拥有分配、创建子 Agent 的权限。
- subagent 仅作为 tool 能力单元，由主 Agent 通过 function call 调用。
- 需要修复当前展示与实现语义不一致的问题。

# 当前状态
已完成实现与验证，待用户确认是否收口归档。

# 初步关注点
- 前端是否直接把 `auto_review_trace` 或 `agent_runs` 数量渲染为“Agent 数量”，导致把 subagent 也算成独立主 Agent。
- 后端动态审核 trace 是否缺少 `orchestrator/main_agent/subagent/tool_call/function_call` 这类层级语义字段。
- 动态审核桥接是否在结果汇总时把“主 Agent 编排”与“子 Agent 执行”扁平化了。

# 本轮结论
- 后端动态审核桥现已为 `ReviewDecision.agent_trace` 注入显式主从语义：
  - `main_agent`：主审核编排 Agent
  - `subagent`：主 Agent 派发的子执行单元
  - `synthesis`：综合裁决节点
- 动态蓝图解析已加入去重约束：
  - 分析型 Agent 按 `role + dimension` 去重
  - 综合 Agent 仅保留一个
  - 蓝图默认标记为由 `main_agent` 创建
- Agent 工厂已收口创建来源校验，仅允许 `main_agent` 派发的蓝图进入实例化。
- 前端 `AgentTracePanel` 已改为优先展示：
  - `X 个主 Agent`
  - `Y 个子 Agent`
  - `Z 个综合裁决`
  不再把所有 trace 条目直接渲染成“XX 个 Agent”。
- 旧 trace 结构保留回退兼容，不会因为历史数据缺少新字段而直接显示错误主从计数。
