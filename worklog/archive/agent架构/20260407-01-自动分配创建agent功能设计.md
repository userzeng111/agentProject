# 自动分配创建 Agent 功能设计

## 问题标题
自动分配创建 Agent 功能设计

## 用户原始诉求
实现自动分配创建 Agent 的功能。由基础 Agent 进行创建，由一个主 Agent（制定 skills 功能）来分配怎么创建其他的 Agent，然后由一个 Agent 进行规划分配这些 Agent 的任务流。

## 详细设计方案

### 核心理念
Master Agent 通过 LLM 分析任务输入，自主决策：
- 需要创建哪些角色 Agent（角色名、职责、评估维度）
- 每个 Agent 的 prompt 模板（由 LLM 生成，非硬编码）
- Agent 数量和权重分配
- 哪些 Agent 可并行、哪些有依赖

Planner Agent 通过 LLM 分析 Agent 列表，自主决策：
- 生成 DAG 任务流（执行顺序、并行分组）
- 依赖关系和数据流向
- 结果汇总策略

### 并行策略
- 新架构放在 `app/agents/dynamic/` 目录，完全不修改现有代码
- 提供 `/api/v2/tasks` 等并行入口，不影响现有 `/api/v1/`
- 对比验证：同一任务分别走新旧两条路径，结果一致后切换

### 架构图
```
用户请求 → Master Agent (LLM 动态分析任务)
         → AgentBlueprint[]（角色/数量/prompt/权重 全由 LLM 决定）
         → AgentFactory → DynamicAgent[]（实例化）
         → PlannerAgent (LLM 动态规划) → TaskDAG
         → TaskOrchestrator → 并行/串行执行 → 汇总结果
```

### 文件结构（独立于现有代码）
```
app/agents/dynamic/

├── registry.py        # AgentRegistry — 管理 Agent 生命周期

├── planner.py         # PlannerAgent — LLM 驱动，动态生成 TaskDAG
├── orchestrator.py    # TaskOrchestrator — DAG 拓扑执行引擎
└── prompts.py         # Master/Planner 的系统 prompt 模板
```
