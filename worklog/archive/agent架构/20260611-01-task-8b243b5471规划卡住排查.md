## 初步结论

- 用户看到一直卡在“规划中”不是浏览器热重载问题，也不是前端流程图可视化单独造成。
- 后端内部已经推进到“章节计划批次审核 / 自动多 Agent 审核”，但对外任务状态和事件流没有同步，导致 UI 仍展示旧的 `planning / outline-revision`。
- 当前任务整体链路不健康，主要有三类问题：
  - 动态 Agent 审核评分解析异常或输出约束不足：多个 Agent 成功返回但评分被解析为 `0.0`，导致自动审核误判失败。
  - `plan_chapter_batch` 对同一 `task_id + batch_no` 不幂等：重试同一批时重复插入 `batch_no=1`，触发唯一约束错误。
  - LangGraph 内部节点进度未及时写入 `tasklog` 对外状态：后台审核和重试过程无法被 `/workspace` 和前端观察到。

## 待讨论修复方向

- 修复动态 Agent 评分提取与输出约束，避免成功响应被误判为 `0.0`。
- 让章节计划批次创建支持幂等 upsert，重试同一批时更新现有批次而不是插入重复记录。
- 在大纲审核、章节计划批次审核、自动 Agent 执行开始/结束等节点写入可观察事件，让前端工作流图能显示真实运行位置。

## 已实施修复

- 动态 Agent 评分解析兼容中文字段，避免模型返回 `评分/得分/总分` 时被解析为 `0.0`。
- 动态 Agent 输出字段兼容中文 `问题/警告/亮点/理由/分析/评价`，降低自动审核结果丢失风险。
- `MASTER_BLUEPRINT_PROMPT` 明确 `outline_review` 可用变量，并要求大纲审核 Agent 使用 `{{chapter_plan}}`。
- `create_chapter_plan_batch()` 改为按 `task_id + batch_no` 幂等更新，避免同一批次重试触发唯一约束。
- 自动章节计划批次审核通过后会标记 DB 批次为 `approved` 并推进 `outline_completed_count`；驳回时标记 `rejected`。
- 大纲审核与章节计划批次生成写入 progress 事件，提升前端流程图对真实阶段的可观察性。
- `/workspace` 在 `pending_review` 缺失时，从 `novel_chapter_plan_batch` 与 `novel_outline_chapter` 回填 `outline_phase / outline_completed_count / outline_total_count`。
