# 流式输出与多轮对话实现

## 问题标题
基于 bailu-2.7 模型 API 实现流式输出与多轮对话

## 用户原始诉求
使用 devlop.txt 中的 bailu API 文档作为参考，针对当前项目实现：
1. 流式输出（SSE 实时推送 LLM 响应）
2. 多轮对话（带历史消息的连续对话）
- 所有输出都必须是流式的

## 当前状态
已完成，待归档

## 分析

### 现有代码状况
- `gateway_client.py`：仅有 `complete()` 和 `complete_json()` 同步方法，**无流式支持**
- `routes.py`：有 SSE 端点但仅用于任务事件推送，**无 LLM 流式输出端点**
- `story_engine.py`：所有生成都是同步等待完整响应
- bailu API：OpenAI 兼容格式，支持 `stream: true` 的 SSE 流式响应

### 实现规划

#### 第一阶段：底层流式能力
1. **`gateway_client.py` 新增 `complete_stream()` 方法**
   - 使用 `httpx` 的流式请求（`client.stream()`）
   - 解析 OpenAI SSE 格式（`data: {...}` 行）
   - 逐 token yield 产出
   - 返回 AsyncGenerator

2. **`gateway_client.py` 新增 `complete_stream_sync()` 方法**
   - 同步版本，用于现有同步调用链路

#### 第二阶段：API 层
3. **新增 API 路由 `/api/chat/stream`**
   - 接收 messages 数组（支持多轮对话历史）
   - 通过 SSE 流式返回 LLM 响应
   - 支持 model 参数选择模型

4. **新增 API 路由 `/api/chat/completions`**
   - OpenAI 兼容端点，同时支持流式和非流式
   - `stream: true` 时走 SSE 流式

#### 第三阶段：集成验证
5. **先用 curl 验证 bailu API 流式可用性**
6. **编写测试用例验证流式输出和多轮对话**

### 影响范围
- `apps/agent-runtime/app/llm/gateway_client.py` - 新增流式方法
- `apps/agent-runtime/app/api/routes.py` - 新增聊天端点
- `apps/agent-runtime/app/domain/models.py` - 可能新增请求/响应模型
- 新增测试文件

### 风险
- bailu API 的流式 SSE 格式需验证是否完全兼容 OpenAI 格式
- httpx 流式请求的超时和连接管理
