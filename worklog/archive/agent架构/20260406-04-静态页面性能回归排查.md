# 静态页面性能回归排查

## 用户原始诉求
- 测试线上当前版本应该是什么样子
- 顺便测试各个窗口的命中延迟
- 对比 `33ba05d8e154e0919f7cb5969fb3a1911bf5456f` 与当前版本，分析为什么旧版本感觉更流畅

## 当前已知上下文
- 线上前端域名为 `https://app.yuegui666.icu`
- 线上后端域名为 `https://api.yuegui666.icu`
- 当前前端已经是 `Cloudflare Pages` 静态托管口径
- 先前已确认 `_next/static/...` 静态资源现在可正常返回 `200`

## 当前状态
- 已创建问题记录
- 正在采集线上页面与静态资源耗时数据
- 正在对比 `33ba05d` 与当前前端实现差异

## 本轮排查记录
- 线上页面静态壳可正常返回 `200`，主要页面包括：
  - `/`
  - `/create/`
  - `/tasks/?id=...`
  - `/review/?id=...`
  - `/result/?id=...`
  - `/archive/`
  - `/archive/detail/?id=...`
- HTML 响应头显示：
  - `cache-control: public, max-age=60`
  - `cf-cache-status: DYNAMIC`
  - `last-modified: Mon, 06 Apr 2026 09:26:03 GMT`
- 静态资源响应头显示：
  - `/_next/static/...` 返回 `200`
  - `cache-control: public, max-age=2592000, immutable`
- 当前前端并非“纯静态数据页”，而是“静态 HTML 壳 + 运行时 API 拉取数据”：
  - 首页加载后请求 `/api/dashboard` 与 `/api/models`
  - 创建页加载后请求 `/api/models`
  - 工作台页加载后请求 `/api/tasks/{id}/workspace`，并尝试建立 SSE
  - 审核页、结果页、归档页也都会在客户端再次请求 API
- 当前线上抽样耗时（本机网络环境）：
  - 静态资源 `/_next/static/...` 首包约 `0.39s ~ 0.51s`
  - HTML 页首包约 `1.1s ~ 3.3s`，个别请求 TLS 握手抖动可到 `5s+`
  - API `/api/health`、`/api/models`、`/api/dashboard`、`/api/tasks/{id}/workspace` 首包约 `1.1s ~ 2.6s`
- 与 `33ba05d` 对比：
  - `apps/web` 范围内仅新增 3 个相关提交：`a5f369d`、`6c99f27`、`7b1d2f6`
  - 这些改动主要是静态站兼容、路由从动态段改为查询参数、Pages 回退配置、端口与 API 地址同步
  - 未发现足以单独解释“明显变卡”的前端重型功能堆叠
- 当前更可疑的体感来源：
  - 页面进入后等待运行时 API 返回，骨架屏持续时间被用户感知为“页面慢”
  - HTML 本身在 Cloudflare 上呈现 `DYNAMIC`，未表现为明显边缘缓存命中
  - 当前测到的波动更像网络/TLS/回源链路抖动，而不是静态导出本身变慢

## 当前结论
- 当前版本仍然是静态站兼容方案，但不是“无接口依赖”的纯静态内容站。
- `33ba05d` 到当前版本的前端差异主要是兼容性修正，不是主要性能回归来源。
- 用户体感较慢的首要怀疑对象是：
  - `api.yuegui666.icu` 的运行时接口延迟
  - `app.yuegui666.icu` HTML 未稳定命中边缘缓存
  - 页面首屏展示依赖接口，导致静态壳虽然快，但内容出现仍受 API 速度制约
