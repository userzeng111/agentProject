# 问题标题
Agent 审核追踪轮次统计修复

# 用户原始诉求
- 章节批次审核页面出现 `4 个主 Agent / 42 个子 Agent / 8 个综合裁决` 这类明显不符合单次派生语义的展示。
- 需要修复 Agent 审核追踪的轮次统计口径，避免把历史审核轮次累计结果误显示成当前轮次。

# 当前状态
已完成修复与验证，待用户确认是否收口归档。

# 初步关注点
- 前端是否应只统计最后一个 `__summary__` 对应的当前轮次，而不是整条累计 trace。
- 后端是否应在每个 summary 条目中补充 `review_type / trace_round / revision_count / batch_index` 等元数据，降低前端误用风险。
- 历史轮次是否需要单独显示为“历史审核记录”，避免继续与当前轮次混淆。

# 本轮结论
- 单次动态审核的派生语义没有问题，仍然是：
  - `1` 个主 Agent
  - `N` 个子 Agent
  - `1` 个综合裁决
- 真实问题在于：
  - 后端会把每轮自动审核结果持续追加到 `auto_review_trace`
  - 前端旧实现直接对整条历史 trace 做主/子/综合统计
  - 因此页面把“累计历史轮次”误展示成“当前轮次”
- 已完成的修复：
  - 前端新增 trace 分段纯函数，按每个 `__summary__` 将历史 trace 切成轮次
  - 审核面板现在只统计最后一轮 trace，历史轮次以 `历史 X 轮` 单独提示
  - 后端 summary 条目新增 `trace_round / review_type / revision_count / batch_index / created_at` 元数据，避免后续再次误用累计 trace
  - 旧 trace 仍兼容：即使没有新元数据，前端也会按最后一个 `__summary__` 取当前轮次
