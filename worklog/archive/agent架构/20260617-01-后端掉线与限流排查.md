# 后端掉线与限流排查

## 用户原始诉求

用户反馈：“掉后端了，你看看我的日志这里是怎么回事的”

## 当前状态

已完成修复，待用户验证与确认是否收口归档提交。日志显示后端进程仍在监听 `127.0.0.1:8000`，`/api/health` 可返回 `{"status":"ok"}`；用户感知的“后端掉线”来自本地限流中间件对高频请求和 CORS `OPTIONS` 预检请求返回 `429`，导致浏览器把 API 调用表现为不可用。

## 已观察到的证据

- 后端进程 `python3` 仍监听 `127.0.0.1:8000`。
- `GET /api/health` 返回 `200`。
- 日志中在连续删除多个任务后，出现多次 `DELETE /api/tasks/... 429` 和 `OPTIONS /api/dashboard 429`、`OPTIONS /api/models 429`。
- CORS 预检请求被限流后，前端会显示接口不可用或事件流断开，容易被误判为后端进程退出。
- 限流窗口过后，`/api/health`、`/api/dashboard` 和带 Origin 的 `OPTIONS /api/dashboard` 已恢复 `200`。

## 修复内容

- 后端限流中间件已豁免全部 `OPTIONS` 预检请求。
- 后端限流中间件已豁免 `/api/health`，保留原有 `/health` 豁免。
- 新增回归测试覆盖 CORS 预检和 `/api/health` 在通用限流打满后仍可访问。
