# web动态路由修复与接口自检skill

## 用户原始诉求
- 当前 `develop` 是用户开发分支
- 网页端“待处理 -> 查看”点击后提示找不到网页，需要修复
- 需要自检其他接口
- 需要把这套检查测试任务流用 skill 形式沉淀下来

## 当前已知上下文
- 前端使用 Next.js App Router
- 首页待处理卡片会跳转到 `/tasks/[id]`、`/review/[id]`、`/result/[id]`、`/archive/[id]`
- 当前前端配置了 `output: "export"`，动态详情页使用了 `force-static + __placeholder__`

## 当前状态
- 已创建问题记录
- 正在定位网页端动态路由与接口契约问题

## 当前方案
- 修复前端动态任务详情页的路由模式，使运行期任务 ID 可访问
- 自检首页、任务页、审核页、结果页、归档页与对应 API
- 将检查流程沉淀为项目 skill，便于后续复用

## 新增部署约束
- 用户确认当前线上发布方式为 `Cloudflare Pages 静态站`
- 因此前端最终方案必须兼容：
  - `output: "export"`
  - 静态产物部署
  - 不能依赖运行期服务端动态路由

## 讨论收敛
- 用户已明确选择采用“Cloudflare Pages 静态站兼容方案”
- 当前进入静态兼容路由设计讨论，暂不继续提交新的代码改动

## 根因结论
- 首页“待处理 -> 查看”打不开网页的直接根因是：
  - `apps/web/next.config.mjs` 开启了 `output: "export"`
  - 同时 `/tasks/[id]`、`/review/[id]`、`/result/[id]`、`/archive/[id]` 都被写成了 `force-static + __placeholder__`
- 这会导致前端只产出占位页，而不会为运行期真实任务 ID 生成对应页面，因此点击真实任务时会落到不存在的静态路径。
- 额外发现的接口层问题：
  - `start.sh` 仍把后端启动到 `8000`，与前端默认 API 基地址 `8001` 不一致
  - `db_repository.py` 存在损坏与写库顺序问题，导致任务索引同步报错
