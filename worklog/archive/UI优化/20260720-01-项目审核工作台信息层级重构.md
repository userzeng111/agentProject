# 项目审核工作台信息层级重构

## 用户原始诉求

点击进入项目后的小说追踪/章节审核页布局不合理：标题和阶段信息占用过多首屏空间，难以追踪有效内容；“进入章节计划审核”等高优先级操作应固定在上方；审核及后续操作内容应采用创建任务页相同的空间利用方式。

## 当前状态

已实施：追踪页改为紧凑工作台并将待审核入口提升到固定头部；审核页使用左侧阶段上下文、中央材料滚动和右侧 Agent 审核追踪。审核决策不再常驻遮挡追踪内容，改由固定头部的“提交审核决策”按需打开右侧抽屉。

## 后续交互讨论

用户反馈固定审核决策会遮挡右侧 Agent 追踪。建议保留追踪页的“进入审核”入口，不把通过/拒绝移到追踪页；审核页默认恢复 Agent 追踪侧栏，并在固定头部提供“提交审核决策”按钮，点击后打开右侧抽屉承载模型选择、审核意见与通过/拒绝操作。抽屉关闭后回到不被遮挡的材料与追踪视图。

## 验证

- ESLint、TypeScript 检查与生产构建通过。
- 已补充审核工作台的独立滚动、桌面决策固定和移动端侧栏折叠回归断言。
- 审核、结果、归档的 Playwright 完整回归（22 项）通过；任务工作台动作分支（14 项）通过。
- 前端单元测试（200 项）通过。
- 审核决策抽屉：桌面与移动端浏览器回归通过，默认追踪可见；打开、关闭抽屉后追踪仍可见；移动端为全屏且无横向溢出。
- 本轮复核通过：`npm run lint`、`npx tsc --noEmit`、`npm test`（200 项）和 `npm run build`。生产构建仅保留既有 `metadataBase` 配置警告。

## 截图初步结论

- 面包屑、阶段条与大标题纵向连续堆叠，首屏大量高度没有服务于审核决策。
- 正文审核内容与通过/拒绝操作横向割裂，正文可读宽度不足，操作卡又没有处在固定且高优先级的位置。
- 需要将项目工作台审核视图改为统一工作台：紧凑上下文栏、顶部固定审核决策条、中央可滚动正文/审核内容，以及按需显示的侧栏摘要。
