# 创建、归档与设置页可用性重构

## 用户原始诉求

创建任务的“任务更详细”界面无法完整查看；归档页的归档列表也被布局卡住；设置页面存在同类问题。需要重构这几个页面，使整体 UI 设计与操作方式更人性化，并符合 UI/UX 使用规范。

## 当前状态

正在进行只读布局排查与 UI/UX 方案设计，尚未修改项目代码。

## 初步排查结论

- 创建、归档与设置页都使用了“固定整屏 + 外层 `overflow: hidden` + 内层 `overflow: auto`”的三层布局。页面标题、告警和内容区共同占用固定高度时，长表单、归档卡片和设置卡片的可滚动区域会被挤压，形成不易发现的嵌套滚动。
- 根布局在桌面端锁定为 `100dvh` 并禁用外层滚动，放大了上述问题；移动端虽然解除高度锁定，但三页的内部滚动实现仍不一致。
- 创建页将全部字段和模型能力说明连续堆叠，缺少信息分组、进度提示和明确的提交入口；归档页和设置页把长列表/表格嵌入独立滚动容器，容易出现内容截断与“列表卡住”的主观体验。
- 目标 UI 文件当前已有未提交改动，后续实施需以增量方式叠加，不能覆盖既有工作区内容。

## 拟议重构方案

1. 将创建、归档、设置三个文档型页面统一为“单一页面级滚动面”：仅这三个路由在主内容区滚动，保留任务工作台与聊天等固定面板页面的现有布局，避免全局改动引入回归。
2. 移除三页当前“页面 Stack 禁止滚动 + 内容卡片单独滚动”的嵌套滚动关系。页面标题与内容均在同一滚动上下文中；桌面端标题栏保持可见的粘性定位，移动端回归普通文档流。
3. 创建页按“基础设定、创作要求、执行选项”重组长表单，在标题栏和表单末尾提供等价的创建入口；保留全部现有字段、校验和模型能力信息，不改变接口语义。
4. 归档页扩大桌面内容宽度，任务卡片改为可换行的元信息布局；分页保留在列表末尾，切页后回到列表标题，窄屏操作按钮占满可用宽度。
5. 设置页按“RAG 同步、同步状态、模型协议”分区；桌面表格仅保留必要的横向滚动，页面纵向不再嵌套滚动；长模型 ID 与来源路径继续自动换行。
6. 统一可访问性与反馈：44px 最小触点、可见焦点、清晰滚动边界、加载/空/错误状态不遮挡内容，并在 375、768、1024、1440 宽度回归。

## 待确认

用户反馈不接受整页纵向滚动，要求采用侧方保留、页面拆分、明确滑动区域及横向布局重构；设置主页只保留主要设置入口并跳转子页面。正在据此修订方案，尚未修改项目代码。

## 修订方案

1. 创建页在桌面端改为三栏工作台：左侧固定步骤导航与完成提示，中间为唯一、可见滚动条的表单工作区，右侧固定显示任务摘要和创建按钮；表单按基础设定、创作要求、执行选项分区。中间工作区是页面唯一可滚动纵向区域，用户无需将鼠标精确移到卡片内。窄屏依次折叠为顶部步骤条、表单区和底部固定操作区。
2. 归档页保留左侧归档总数与返回入口，中间列表作为唯一滚动区；桌面卡片按“作品信息/统计与模型/操作”横向分配，窄屏改为纵向卡片。分页固定在列表区域底部，不再随卡片内容滚离视野。
3. 设置主页改为设置总览，只显示“知识库同步”和“模型协议”两个主要入口、当前状态和风险提示；分别跳转至 `/settings/rag` 与 `/settings/models` 子页面。子页面各自拥有固定侧栏和一个清晰的内容滚动区，避免把 RAG 作业、模型表格堆在同一页。
4. 保留现有 API、数据与直接访问旧 `/settings` 路由的兼容性；为新子页面提供返回设置总览的路径。

## 实施结果

- 新增统一 `WorkbenchPageLayout`：桌面端固定侧栏与可选右侧摘要，中央区域为唯一纵向滚动面；工作台路由在根布局中固定视口，移动端隐藏侧栏并保留中央操作入口。
- 创建页改为“基础设定、创作要求、执行选项”三个可导航分区。桌面端显示步骤侧栏、表单区和任务摘要/创建按钮；窄屏仍可直接提交和访问全部字段。
- 归档页改为左侧归档概览、中央归档列表和固定分页栏。归档卡片在桌面端横向组织作品信息、创作信息与操作，窄屏自动纵向展开。
- 设置页已拆为设置总览、`/settings/rag/` 与 `/settings/models/`。总览仅展示状态、风险和入口；RAG 同步与模型协议在各自子页中操作，保留 API、二次确认和后台进度语义。
- 更新路由单测和设置相关浏览器测试；新增桌面滚动边界回归，验证创建、归档、设置均由中央工作区承担纵向滚动，页面本身不回退为纵向滚动。
