# 章节审核页布局问题定位

## 用户原始诉求

“http://localhost:3000/p/task_b0981edf49/?view=review&library_tab=pending 这个章节审核还是存在问题”。

## 当前状态

已完成实现与真实页面验证，并经用户确认收口归档。通用工作台栅格已恢复；审核页从 900px 起使用左侧项目追踪。

## 范围

- 路由：`/p/task_b0981edf49/?view=review&library_tab=pending`
- 前端：章节审核工作台、审核决策操作与项目上下文导航。
- 不涉及任务审核数据、后端状态或提交行为的修改。

## 复现与根因

- 在 1440×900 真实浏览器中，`review-context-pane` 被渲染为整行顶部区（高度约 324px），审核材料滚动区只剩约 363px，章节内容首屏被明显压缩。
- 在 1024×900 中，审核左栏完全隐藏。
- `WorkbenchPageLayout` 的旧版布局分支把断点对象错误展开为 `sx` 顶层字段，未实际生成 `grid-template-columns`；因此即使左栏可见，也不会形成左右网格。
- `TaskReviewClient` 仍在使用旧版分支，且未指定 900px 的左栏阈值。

## 拟定修复

1. 修正 `WorkbenchPageLayout` 的旧版响应式栅格对象，让默认工作台正确生成左右列。
2. 审核工作台显式采用 900px 左栏阈值，与项目追踪、设置页保持一致。
3. 新增 1024px 与 1440px 浏览器回归：左栏应位于材料区左侧，审核材料滚动区不再被顶部导航挤压。

## 实施与验证

- 已统一 `WorkbenchPageLayout` 的媒体查询栅格生成，默认工作台恢复正确的左右列。
- 审核页已显式采用 900px 左栏阈值。
- 指定任务在 1440×900 真实浏览器中：左栏宽度 208px，审核材料区位于右侧且高度恢复为约 703px。
- 已通过 `npm run lint`、`npx tsc --noEmit`、审核/结果/归档浏览器回归（13 项通过）及 `git diff --check`。
