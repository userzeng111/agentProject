# AI 对话与模型验证 UI 回归排查

## 用户原始诉求

用户反馈当前阶段对 AI 对话和模型验证进行了破坏性修改：UI 中无法进行模型验证调试，也无法选择聊天模型；同时页面出现异常重叠、穿模现象。

## 当前状态

修复、自动化验证与独立代码审查均已完成。用户已于 2026-07-10 完成界面验收并明确同意收口；本记录已归档并提交。

## 排查范围

- `/chat` 聊天模型目录加载、模型选择、选择器禁用条件与提交条件。
- 模型验证入口、URL 参数回填、验证流请求与错误反馈。
- 桌面端和移动端的布局、层叠上下文、弹窗/下拉菜单定位与遮挡。
- 前后端 `/api/models` 返回、浏览器网络请求、控制台错误和服务端日志之间的数据流。

## 当前假设

- 已证实：聊天模型选择器将占位 `MenuItem` 与实际模型项包在 React `Fragment` 中。MUI 非原生 `Select` 要求 `MenuItem` 为直接子节点，否则不会将选择事件注入实际菜单项。
- 已证实：当前供应商目录返回 34 个模型，菜单未设置最大高度与内部滚动，34 个双行菜单项展开后高度约 1885px，覆盖聊天输入区和移动端验证入口。
- 已排除：模型目录为空、浏览器控制台异常、模型验证查询接口失败和验证链接跳转失败。

## 已确认事实与复现证据

- `GET /api/models?refresh=true` 返回 HTTP 200，目录中有 34 个 `metadata.source="gateway"` 的模型，包含已验证样本；前端筛选函数也将其识别为可聊天模型。
- 在桌面 `1440x900` 与移动 `390x844` 的真实 Playwright 浏览器中，点击聊天模型选择器均打开 35 个菜单项（含占位项），但菜单项 DOM role 保持 `menuitem`，没有被 MUI 注入为 `option`。
- 点击 `bailu-turing` 后，点击事件确实到达该菜单项；0ms、25ms、100ms、500ms 四个状态快照中，选择器仍为“请选择聊天模型”、菜单仍展开、会话 localStorage 的 `model` 仍为空。这说明 `handleModelChange` 没有触发，而不是后续状态被清空。
- 当前代码改造前实际模型项通过 `selectableModels.map(...)` 直接作为 `TextField select` 子节点；改造后为增加空占位项新增了 `Fragment` 包裹，正是选择失效的引入点。
- MUI 5.18.0 本地源码明确规定：非原生 `Select` 的 `MenuItem` 必须是直接子节点；其选择逻辑只对直接 children clone 并注入 `onClick`、`role="option"`。
- 未限制菜单高度时，桌面菜单尺寸约 `229 x 1885px`，移动端约 `270 x 1897px`，超出视口并覆盖输入与操作区，形成用户看到的重叠穿模。
- 使用 `/chat?model=bailu-2.7-free&validate=1` 直接进入时，模型可回填，`GET /api/model-validation` 返回 HTTP 200，桌面和移动端的“重新验证”按钮均为可用状态。因此后端模型验证调用链未被本次问题阻断。

## 拟定最小修复方案

1. 将占位项和模型项改为同一层级数组，确保所有 `MenuItem` 都是 `TextField select` 的直接子节点；保留无默认模型、空选择和手动选择语义。
2. 为菜单增加视口受限的最大高度、纵向滚动与稳定宽度；移动端以安全视口高度计算，避免覆盖输入区和验证入口。
3. 补充浏览器回归测试：真实点击任意模型后选择值与会话存储同步、验证按钮启用、菜单高度不超过视口约束；覆盖桌面与移动端。
4. 运行前端单测、E2E 定向测试、Lint、生产构建，并用真实浏览器截图复核桌面/移动端；不触发真实供应商重新验证，避免产生额外调用与改写验证记录。

## 审查修复与最终复核（2026-07-10）

- 独立审查发现：模型目录尚未返回时，选择同步逻辑会把已恢复的会话模型清空并持久化，导致用户刷新页面后丢失手动选择。
- 已补充延迟 `/api/models` 响应的刷新回归测试；修复前该测试稳定复现 `gpt-5.4` 被写成空值，修复后桌面与移动端均通过。
- 修复方式：新增 `modelCatalogLoaded` 门禁。仅在目录请求成功返回后，才根据当前目录清理失效模型；请求尚未完成或失败时保留已保存选择，不允许发送，且不回退到默认或首项模型。
- 最终独立复审结论：无阻断问题。目录成功后仍会清理下线模型，`model-selection` 仍只返回已保存且目录存在的模型或空值。
- 最终验证：聊天/设置 E2E Chromium 9/9 通过、mobile-chromium 9/9 通过；前端单测 130/130 通过；ESLint、TypeScript 检查和生产构建均通过。构建仅有既有 `metadataBase` 提示。
- 测试环境：前端已运行于 `http://localhost:3000`；后端已通过 tmux 会话 `agentproject-backend` 运行于 `http://localhost:8000`。连续健康检查通过，当前 `/api/models` 返回 34 个模型。
