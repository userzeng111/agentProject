# Agent 状态工作流可视化设计

## 用户原始诉求

分析当前项目，并为现有 agent 流程设计“状态工作流图可视化”能力。要求能看到当前工作流已经走到什么位置，以管线流程输出形式观察当前所处阶段，并结合 UI/UX 做设计分析。

## 当前状态

已完成第一版分层状态卡实现，但用户反馈展示形态不符合预期，需重新讨论并调整为流程图式可视化。

## 初步关注点

- 需要先梳理当前后端工作流节点、状态字段、事件流与前端任务页展示入口。
- 需要确认可视化是“静态阶段图 + 当前高亮”，还是“实时流转 + 历史轨迹 + 子流程展开”。
- 需要结合现有 UI 风格评估落点页面、信息密度、交互成本与移动端适配。

## 当前代码观察

- 后端主工作流 `apps/agent-runtime/app/graph/main_graph.py` 已明确建模为节点图：
  - `normalize_request -> prepare_outline_context -> plan_story -> review_outline`
  - 之后进入三段循环：大纲审核循环、章节对生成/审核循环、全文验证/修复循环，最后 `assemble_result`
- 后端已向前端暴露多层状态信息：
  - 总任务状态：`TaskStatus`
  - 当前阶段：`current_stage`
  - 当前单元：`current_unit`
  - 最近事件流：`recent_events`
  - Supervisor 粗粒度子任务：`supervisor_plan`
  - Agent 运行记录：`agent_runs`
- 前端工作台 `apps/web/src/features/task-run/task-run-client.tsx` 当前只有 4 步粗粒度步骤条：
  - `创建 -> 运行 -> 审核 -> 结果`
  - 不能表达大纲阶段、章节批次、验证修复、取消/失败落点，也不能显示“当前卡在哪个节点”
- 当前前端已有可复用信息区：
  - 实时日志
  - 章节进度
  - Supervisor 列表
  - 模型思考过程
  但这些信息彼此割裂，尚未形成统一的“流程可视化主视图”。

## UI/UX 基线

- 全站已建立暖色文学风格变量：米色纸张背景、墨绿色主色、琥珀辅助色、玻璃态卡片。
- 当前任务页是信息密度较高的工作台型页面，适合做“主流程总览 + 详情下钻”，不适合再塞一块过于复杂的纯装饰图。
- 仓库内已有 UI 优化结论强调：
  - 保持现有暖色古典基调
  - 优先使用 MUI 原生组件
  - 通过分区、折叠、步骤指示器降低认知负担

## 第三方方案调研结论

- MUI `Stepper` 适合保留为粗粒度生命周期导航，但不适合表达循环、分支和当前节点落点。
- React Flow（`@xyflow/react`）支持：
  - 自定义节点/边
  - `fitView`
  - 只读展示
  - 关闭拖拽/连接交互后作为工作流观察图使用
- 如果需要真正的“管线流程图 + 当前节点高亮 + 分支循环表达”，React Flow 更匹配；如果只做线性阶段高亮，MUI Stepper 足够。

- 当前推荐落点：
  - 替换现有顶部粗粒度 4 步步骤条

  - 形成一个新的“工作流总览主卡”
  - 保留现有 Tabs 作为下钻详情层，而不是再新增独立页面

## 已确认的第一版设计边界

- 基于现有 `/api/tasks/{task_id}/workspace` 返回数据优先实现，不先要求后端新增专用工作流接口。
- 主流程图优先表达：
  - 大纲审核阶段
  - 章节计划批次阶段
  - 正文章节对生成/审核循环
  - 全文验证/修复循环
  - 完成 / 取消终态
- `supervisor_plan` 与 `agent_runs` 作为辅助视角保留在现有详情区，不直接混入第一版主流程图主干。

## 分层版进一步分析

### 页面落点

- 替换 `TaskRunClient` 顶部现有 `WORKFLOW_STEPS` 4 步步骤卡。

  - 请求摘要与操作区
  - 现有 Tabs 详情区

### 主流程总览

- 主流程建议采用 6 个用户可读阶段：
  - 任务准备
  - 大纲规划
  - 章节计划
  - 正文创作
  - 全文验证
  - 结果整理
- 主卡需要显示：
  - 当前阶段高亮
  - 已完成阶段
  - 阻塞 / 失败 / 取消状态
  - `current_stage` 与 `current_unit` 技术游标
  - `progress` 百分比
  - 最近一条关键事件摘要

### 子流程块

- 子流程块一：大纲与章节计划
  - 覆盖 `planning / waiting_outline_review`
  - 使用 `outline_phase / outline_completed_count / outline_total_count`
  - 表达总纲审核与章节计划批次审核两个阶段
- 子流程块二：正文生成与章节审核
  - 覆盖 `drafting / waiting_chapter_review / ready_for_batch`
  - 使用 `novel_progress.completed_chapter_count / planned_chapter_count / next_chapter_number / current_generating_chapter_number`
  - 表达章节对生成、章节门禁、章节审核、累计章节和等待继续创作
- 子流程块三：全文验证与修复
  - 覆盖 `waiting_verification_review / assembling / completed`
  - 使用 `current_stage / current_unit / recent_events`
  - 表达全文验证、验证审核、问题修复、结果整理和完成

### 交互建议

- 第一版建议做“可观察 + 轻量联动”：
  - 主流程节点可点击切换到对应详情 Tab
  - 子流程块默认只读，可展开 / 收起
  - 当前活跃子流程默认展开，其余折叠
- 联动关系建议：
  - 大纲 / 验证审核阶段：跳转审核页或切到实时日志
  - 正文创作阶段：切到章节进度 Tab
  - Supervisor 信息继续留在 Supervisor Tab，不并入主流程

### 暂不做范围

- 不引入 React Flow 或其他重型流程图库。
- 不新增后端工作流拓扑接口。
- 不把 `supervisor_plan` 直接渲染为主流程。
- 不做独立监控页。

## 用户反馈与方向调整

- 用户反馈：当前“分层状态卡”不是期望的可视化形式。
- 新目标：
  - 需要类似流程图的可视化。
  - 需要显示各个任务阶段的流转。
  - 需要显示派发的 Agent 做了什么事情。
  - 审核阶段应能展示主 Agent 分配多个子 Agent 执行审核任务，并展示各 Agent 状态。
- 代码现实：
  - 审核页已有 `auto_review_trace` 数据，包含 `main_agent / subagent / synthesis`、`parent_agent_id`、`status`、`score`、`issues`、`reasoning` 等字段。
  - 当前 `AgentTracePanel` 以列表方式展示这些数据，不能表达主从派发关系。
  - 任务工作台 `/workspace` 当前不返回 `auto_review_trace`，因此若要在工作台主视图展示 Agent 派发图，需要扩展后端响应，或由前端额外请求 `/review`。
  - 现有动态审核 trace 多数在审核完成后一次性落库，若要显示真正实时的 `pending/running/completed/failed` 状态，需要后端在编排执行过程中持续发事件或写入中间状态。

## 新方案关注点

- 从“分层状态卡”调整为“流程图 / DAG 视图”。
- 需要区分两类图：
  - 主工作流阶段图：小说任务从准备、大纲、章节、验证到完成的阶段流转。
  - Agent 派发图：审核节点内部主 Agent -> 子 Agent -> 综合裁决的派发关系与状态。
- React Flow（`@xyflow/react`）更适合承载这种节点/边可视化；若不引入依赖，则需要自绘 SVG/HTML DAG，交互能力会弱一些。

## 用户选择

- 用户选择 `B：React Flow 图谱版`。
- 新实现目标：
  - 前端引入 `@xyflow/react`。
  - 用节点 / 边方式展示主工作流阶段流转。
  - 在审核阶段展示 `主审核编排 Agent -> 多个子 Agent -> 综合裁决 Agent`。
  - 复用现有 `auto_review_trace` 的主从关系、状态、评分和问题信息。
  - 工作台优先展示“主流程图 + 当前/最近审核 Agent 图摘要”。
  - 审核页可复用 Agent 派发图，替代或补强当前列表式 `AgentTracePanel`。

## React Flow 图谱版实施结果

- 已引入 `@xyflow/react`，并在前端全局加载 React Flow 样式。
- 已将任务工作台顶部可视化改为流程图式只读画布：
  - 主工作流图展示任务准备、大纲规划、章节计划、正文创作、章节审核、全文验证、结果整理等阶段。
  - 当前阶段、已完成阶段、失败 / 取消 / 等待状态通过节点状态和边样式表达。

- 已新增 Agent 派发图：
  - 基于当前审核轮次 `auto_review_trace` 派生 `主审核编排 Agent -> 子 Agent -> 综合裁决 Agent` DAG。
  - 子 Agent 节点展示角色、任务说明、状态、评分、问题数和失败信息。
  - 综合裁决节点展示当前轮次审核结果与汇总分。

- 设计边界：
  - 当前实现展示的是已落库的审核 trace 和最新工作台状态。
  - 真正执行中的 `pending/running` 逐步刷新，仍依赖后端在 Agent 编排过程中持续写入中间事件，属于后续事件化改造范围。
