# 项目与设置侧栏导航纠正

## 用户原始诉求

“项目追踪是在左边侧栏，而不是在顶上，这个是错的；设置中的设置侧栏也是”。

## 当前状态

已完成实现与验证，并经用户确认收口归档。项目任务追踪与设置导航的左栏显示阈值已统一为 900px，中央顶部已移除重复的项目跟踪说明。

## 现状与结论

- 项目工作台已将 `ProjectWorkbenchContext` 作为 `WorkbenchPageLayout.navigation` 传入，设计意图正确；但中央标题仍重复展示任务跟踪上下文，容易被误认为顶部导航。
- 设置页的 `SettingsNav` 同样传入左侧导航槽位，窄屏才以顶部快捷链接替代；需要复核其桌面断点与中央页头，避免把“设置”重复渲染为顶部侧栏。
- 本次应统一两套工作台的左侧导航呈现和窄屏替代规则，保留现有路由、任务状态与设置页面语义。

## 拟定处理

1. 桌面端将项目阶段与设置分区作为唯一的左侧持久导航；中央顶部仅保留当前页面标题、简洁状态和高优先级动作。
2. 清理会与左侧导航重复的中央说明，减少标题区高度，释放任务追踪的内容空间。
3. 在窄屏使用紧凑横向步骤/快捷链接，保留 `aria-current`、可见焦点和不横向溢出。
4. 补充桌面、窄屏断点的浏览器回归，验证左栏可见、顶部不重复、中央工作区单独滚动。

## 实施与验证

- 项目工作台和设置工作台均显式使用 `responsiveSlots={{ navigation: "md" }}`，在 900px 起使用左栏。
- 设置页的窄屏快捷导航与该阈值一致，左栏可见时不再重复显示。
- 项目中央页头仅保留任务标题、模型摘要、状态与高优先级审核动作。
- 已通过 `npm run lint`、`npx tsc --noEmit`、`npx playwright test e2e/side-navigation.spec.ts --project=chromium`（2 项通过）及 `git diff --check`。
