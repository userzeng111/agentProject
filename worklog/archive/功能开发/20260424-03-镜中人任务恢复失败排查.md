# 问题标题
镜中人任务恢复失败排查

## 用户原始诉求
用户在尝试恢复"镜中人"任务时收到后端返回：
`{"detail":"当前任务不能按原始输入重新开始。"}`

用户要求先试图恢复该任务。

## 最终结论

### 根因
1. **Graph checkpoint 停在生成节点**：任务被恢复到 `waiting_verification_review` 后，LangGraph checkpoint 仍停留在 `draft_chapter_pair` 节点。用户点击"继续"时，`Command(resume=...)` 被生成节点消费而非审核中断节点，导致 `generate_chapter_pair` 重新运行。
2. **LLM 输出缺少 `content` 字段**：重新运行时模型输出缺少 `content` 字段，`ChapterDraft.model_validate` 触发 `Field required` 校验崩溃。
3. **前端缺失 import**：`task-run-client.tsx` 缺少 `CircularProgress` 和 `Collapse` 的 MUI import，导致运行时组件未定义报错。

### 修复内容
- `apps/agent-runtime/app/application/task_service/runner.py`
  - `_resume_task_sync` 中增加 `as_node` 强制校准：在 `graph.invoke(Command(resume=...))` 前，若 checkpoint 存在，通过 `graph.update_state(..., as_node=对应审核节点)` 将状态校准到正确的审核中断节点。
- `apps/agent-runtime/app/llm/story_engine.py`
  - 新增 `_normalize_chapter_payload` 静态方法，对 LLM 输出进行防御性字段填充。
  - 在 `generate_draft`、`generate_chapter_pair`、`revise_chapter_pair` 三处 `ChapterDraft.model_validate` 前应用该规范化。
- `apps/agent-runtime/app/application/task_service/recovery.py`
  - 放宽 `_can_recover_chapter_review` 与 `_can_recover_verification_review`，允许 `waiting_manual_action` 状态下存在 `pending_review` 时执行恢复。
  - `_preview_recover_to_stable` 统一使用 `_can_recover_*` 方法替代直接条件判断。
- `apps/web/src/features/task-run/task-run-client.tsx`
  - 补充 `CircularProgress` 与 `Collapse` 的 MUI import。
