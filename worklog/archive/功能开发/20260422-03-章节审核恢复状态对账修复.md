# 问题标题
章节审核恢复状态对账修复

# 用户原始诉求
- `POST /api/tasks/{id}/resume` 在审核页点击通过时返回 `400 Bad Request`。
- 实际报错为：`当前任务缺少章节批次记录。`

# 当前状态
已完成修复与验证，待用户确认是否收口归档。

# 根因
- 某些旧任务或经历过异常恢复的任务会出现：
  - task 文件状态仍停留在 `waiting_chapter_review`
  - `pending_review` 仍是旧的 `chapter_pair_review`
  - 但小说项目表 `novel_project` 已经推进到 `waiting_verification_review`
  - 同时没有 active batch
- 旧实现中：
  - `get_review()` 会直接把这个过期章节审核继续返回给前端
  - `resume_task()` 在章节审核分支强依赖 `get_active_batch()`，因此直接抛出 `当前任务缺少章节批次记录。`

# 本轮修复
- 在 `TaskService` 新增“任务审核状态 vs 小说项目状态”的对账逻辑：
  - 若任务仍是 `waiting_chapter_review`
  - 但小说项目已经推进到 `waiting_verification_review` 或已完成全部章节
  - 且 active batch 缺失
  - 则自动把任务纠正到 `verification_review`
- `get_review()` 和 `resume_task()` 都会先执行这层对账，避免继续把过期章节审核暴露给前端或在提交时 400。

# 验证
- 定向红灯测试：
  - stale `chapter_pair_review` 会被 `get_review()` 自动纠正为 `verification_review`
  - stale `chapter_pair_review` 在 `resume_task()` 中不再因缺失批次记录而报错
- 回归测试：
  - `uv run python -m unittest tests.test_task_service_review_resume tests.test_batched_chapter_generation tests.test_graph_auto_review_escalation -v`
  - 结果：`29` 个测试全部通过
- 真实接口复验：
  - `GET /api/tasks/task_cd7b8d43ed/review` 已从旧章节审核切到 `verification_review`
  - `POST /api/tasks/task_cd7b8d43ed/resume` 不再返回 `400`
