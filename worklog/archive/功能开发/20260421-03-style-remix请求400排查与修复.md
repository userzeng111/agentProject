# 问题标题
style_remix 请求 400 排查与修复

# 用户原始诉求
用户在选择 `style_remix` 模式后创建任务，任务在运行时失败，摘要为：
`后台任务异常：调用聊天补全失败，状态码 400，响应：{"error":{"message":"Invalid request Error","type":"invalid_request_error","param":"","code":null}}`
要求定位原因并修复。

# 当前状态
已完成修复，待验证手测：已将未验证网关模型拦截在小说任务流之外，避免用户在 `style_remix` 等模式下选到会直接返回 `400 Invalid request Error` 的模型。

# 当前已知信息
- 用户请求摘要：
  - 模式：`style_remix`
  - 题材：`都市`
  - 风格：`保留原文的风格特色，但是也要自己的新东西`
  - 额外要求：存在修罗场，男主是医生
- 前端工作台显示：
  - 任务状态：`failed`
  - 执行摘要：聊天补全接口返回 `400 Invalid request Error`
- 问题只在用户切换到风格复刻模式后暴露，说明很可能与 `style_remix` 下的请求装配、风格上下文、参考材料或模型选择有关。

# 当前排查结论
- 失败任务：`task_076ebf1204`
  - 模型：`K2.6`
  - `style_profile_id`：`wozhenmeixiangchongshengya`
  - `reference_text` 长度：`0`
- 对比结论：
  - 同环境下，`glm-5.1` 的最小 `chat/completions` 请求可正常返回
  - 同环境下，`K2.6` 的最小 `chat/completions` 请求直接返回与任务一致的 `400 Invalid request Error`
- 说明：
  - 当前问题主因不是 `style_remix` 额外参考文本过长
  - 更接近“创建页允许选择了当前项目未验证、且实际不兼容小说工作流的模型”

# 本轮修复目标
1. 后端拒绝未完成兼容性验证的模型进入小说任务流，提前返回明确错误
2. 前端创建页对这类模型显示“未验证/不可用于小说工作流”，避免误选
3. 为模型目录和任务创建链路补回归测试

# 本轮实现结果
- 后端：
  - `apps/agent-runtime/app/llm/model_catalog.py`
    - 为网关返回但未纳入项目注册表的模型补充：
      - `metadata.compatibility = "unverified"`
      - `capabilities.features.novel_task_supported = false`
  - `apps/agent-runtime/app/application/task_service.py`
    - `create_task()` 现在会在进入小说任务流前校验模型兼容性
    - 未验证模型会直接报错：
      - `模型 K2.6 未完成兼容性验证，暂不支持小说任务流`
- 前端：
  - `apps/web/src/lib/types.ts`
  - `apps/web/src/lib/api.ts`
  - `apps/web/src/features/task-create/create-task-client.tsx`
    - 已透传 `metadata.compatibility`
    - 未验证模型在创建页会显示为 `（未验证）`
    - 未验证模型在创建页会被禁选
    - 若当前选择落在未验证模型上，会自动切回首个已验证模型

# 当前结论
- 当前问题主因不是 `style_remix` 提示词本身，而是创建页允许用户选择了当前项目未验证的 `K2.6` 模型。
- 修复后，用户在小说任务流中不再会因为误选这类模型而跑到中途才收到 `400`。
