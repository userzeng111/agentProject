# 执行链路异常与自动审核全量测试

## 用户原始诉求

1. 任务运行失败，报错 "Expecting value: line 1 column 1 (char 0)"
2. 当前主 CTA 显示"查看恢复方案"，推荐动作是"按原始输入重新开始"
3. 用户困惑：已经打开了自动审核，为什么还是需要人工审核并确定
4. 要求分析执行任务链路，定位问题根因
5. 要求走一次完整测试：无自动审核全流程 + 开启自动审核全流程
6. 要求使用 agent team 模式并行执行，提高执行效率
7. **新增**：空响应保护需实现连续重试（类似 Claude Code / OpenCode 的调用逻辑），单次空响应当重试，连续 N 次无结果才报错

## 调查结论

### 问题一：Expecting value 错误

**根因**：上游 API（api.udcode.cn）偶发返回 HTTP 200 OK 但响应体为空字符串，`gateway_client.complete()` 中 `response.json()` 解析空内容时抛出 `json.JSONDecodeError: Expecting value: line 1 column 1 (char 0)`。

**日志证据**：
- `llm_complete_failed model=MiniMax-M2.7-highspeed messages=2`
- 后台任务异常后被 `_mark_failed_unless_stable` 捕获，因任务已进入 `waiting_manual_action` 状态，跳过失败覆盖

**影响**：LLM 调用失败导致工作流/审核节点崩溃，任务卡死。

### 问题二：自动审核开启后仍需要人工审核

**调查结论**：系统设计上，auto_review 确实支持自动通过，但需要满足多个条件：

1. **全局开关默认关闭**：`settings.auto_review` 默认 `False`（`config.py:31`），需通过环境变量 `AUTO_REVIEW=true` 开启
2. **任务级可覆盖**：`task.auto_review` 若不为 None，则优先于全局设置（`core.py:418-421`）
3. **自动通过条件**：
   - `auto_review=true` 且 `auto_review_executor_available=true`
   - `execute_auto_review()` 返回 `decision.approved=true`
   - `should_interrupt_manual_review()` 返回 `False`
   - 此时工作流直接路由到下一节点，不调用 `interrupt()`
4. **评分阈值**：outline ≥70、chapter ≥65、verification ≥80（`models.py:579-581`）

**用户困惑的可能原因**：
- 用户以为 auto_review 已经开启，但实际全局默认是 False
- 或者 auto_review 已开启但评分未过线，导致 approved=false，进入人工审核
- 或者 auto_review 执行异常（如上游 API 故障），fallback 到人工审核

### 问题三：恢复链路问题

当任务后台异常时，`_mark_failed_unless_stable` 尝试标记失败。但如果任务已进入 `waiting_manual_action` 等稳定状态，则跳过失败覆盖。这导致异常原因被隐藏，用户只能看到"查看恢复方案"，而不知道真实失败原因。

## 修复实施记录

### Agent A：Gateway 客户端健壮性修复（空响应重试 + 指数退避）

**文件**：`apps/agent-runtime/app/llm/gateway_client.py`

- `complete()` 方法增加3次重试循环，指数退避（1s → 2s）
- 空响应、JSONDecodeError、GatewayClientError 均触发重试
- 每次重试记录 `llm_complete_retry` 日志
- 连续失败抛出结构化错误，包含重试历史

**新增测试**：`tests/test_gateway_empty_response_retry.py`（5个测试全部通过）

### Agent B：自动审核链路可见性修复

**文件**：`models.py`, `queries.py`, `types.ts`, `task-run-client.tsx`, `core.py`

- `TaskSummary` 增加 `auto_review: bool` 字段
- `_to_summary()` 从 `task.auto_review` 取值返回
- **修复缺陷**：`create_task()` 中 resolved auto_review 值未持久化到 TaskRecord，导致查询始终返回 False
- 前端工作台请求摘要卡片增加 Chip 展示「自动审核：开启/关闭」

### Agent C：审核节点异常日志增强 + 异常信息透传

**文件**：`outline.py`, `chapter.py`, `verification.py`, `main_graph.py`

- 三个文件顶部增加 `get_logger` 导入
- `review_outline()` / `review_chapter_pair()` / `review_verification()` 增加 auto_review 状态 INFO 日志
- except 块增加 ERROR 日志（`exc_info=True`）
- **关键修复**：发现 `interrupt()` 第一次调用时抛出 `GraphInterrupt` 异常并停止 node 执行，导致 `decision.comment` 中的异常信息无法通过返回值传递。解决方案：将 `comment` 参数传入 `interrupt()` 的 payload summary 中，使异常信息直接出现在用户可见的审核摘要中
- `main_graph.py` 中的包装函数同步增加 `comment` 参数透传

### Agent D：任务错误透传增强

**文件**：`core.py`, `queries.py`, `types.ts`, `task-run-client.tsx`

- `_mark_failed_unless_stable()` 跳过失败覆盖时，写入 `task.error_recorded` 事件日志
- `_to_summary()` 倒序查找 `task.error_recorded` 事件，提取详情到 `last_error_detail`
- 前端工作台在「当前任务需要人工处理」下方展示红色异常详情
- **修复缺陷**：`_sync_result()` 的 COMPLETED 路径未保存 `auto_review_trace`，导致自动审核通过后 trace 丢失。已补充保存逻辑
