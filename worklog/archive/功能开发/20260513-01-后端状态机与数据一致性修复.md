# 后端状态机与数据一致性修复

## 用户原始诉求

修复以下三个后端状态机与数据一致性问题：

1. **审核通过后 checkpoint 与数据库状态不一致**：`resume_task` 中审核通过后调用 `workflow_engine.resume` 前，LangGraph checkpoint 状态可能与数据库 `novel_project` 状态不同步。
2. **删除任务孤立记录**：`delete_task` 只删除 task_store 文件，数据库中 `novel_project`、`novel_generation_batch`、`novel_outline_chapter` 等关联记录未被清理。
3. **归档操作原子化**：`_archive_completed_task` 当前是复制文件 → 删除原文件，中间崩溃可能部分归档。

## 方案

### 任务1：resume_task 审核通过后同步校验

在 `review.py` 的 `resume_task` 中，对于 `approved=True` 且最终会进入后台 workflow 的分支（`chapter_pair_review` 无 novel_project、verification_review、outline_review 驳回/通过需后台执行的情况），在调用 `workflow_engine.resume` 前（实际在 `_resume_task_sync` 中），添加同步校验：

- 读取当前 `novel_project` 状态
- 如果 `project.status` 与 checkpoint 中的状态不一致，以数据库状态为准，调用 `workflow_engine.update_state(task_id, ...)` 对齐
- 若 `get_state` 或 `update_state` 不可用（旧接口），静默跳过

具体插入点：在 `runner.py` 的 `_resume_task_sync` 方法中，`_rehydrate_resume_state_if_needed` 之后、设置 as_node 之前（或之后），加入 `_sync_checkpoint_with_novel_project_if_needed` 调用。

### 任务2：delete_task 级联删除数据库记录

在 `task_store.py` 的 `delete_task` 中，删除文件后，使用 `get_session()` 执行 SQL 删除：

```sql
DELETE FROM novel_outline_chapter WHERE task_id = ?
DELETE FROM novel_generation_batch WHERE task_id = ?
DELETE FROM novel_project WHERE task_id = ?
DELETE FROM tasks_index WHERE task_id = ?
```

删除失败只记录 warning，不影响主流程。

### 任务3：归档操作原子化

在 `task_store.py` 的 `_archive_completed_task` 中，改为三步原子操作：

1. 将任务目录复制到临时归档路径（`archive/.tmp_{task_id}`）
2. 用 `os.replace` 或 `shutil.move` 原子移动到正式归档路径
3. 确认移动成功后删除原任务目录

如果第3步失败，记录 warning 但不回滚（数据已在归档中）。
