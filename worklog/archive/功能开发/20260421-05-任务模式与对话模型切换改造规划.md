# 问题标题
任务模式与对话模型切换改造规划

# 用户原始诉求
采用 agent team 开启团队模式规划并分配以下任务：
- ai 对话在切换了默认模型后无法更换模型回答；
- 任务模式修改，改为全新原创、同人创作、风格复刻；
- 三个模式都支持长篇创作、中篇创作、短篇创作三个选项；
- 长篇指大纲章节数 400 章以上，中篇 80-400 章，短篇 8-80 章；
- 具体章节数分配由创建的小说主 agent 进行分配管理；
- 目标字数改为“单章字数下限”，允许在此基础上上浮 10%-30%；
- 除了全新原创之外，同人创作、风格复刻都可以加载风格实例；
- 区别为：同人创作基于原本世界观创作，风格复刻借用原本风格创作。

# 当前状态
已完成实现与 fresh 验证，已满足收口条件。

# 当前结论
- 本轮先做设计和任务分配，不直接改代码。
- 已确认现状：聊天接口协议层支持传 `model`，但聊天页当前没有真正落地“手动切模型”UI 与状态持久化。
- 已确认现状：默认模型切换后聊天未生效，主要风险点在后端路由对默认模型的闭包缓存。
- 已确认现状：任务 `mode` 当前混合了承载“创作类型”和“篇幅层级”两类语义，不适合继续扩展。
- 已确认现状：当前章节数主要由 `StoryPlan.chapter_plan` 长度隐式决定，尚未显式表达“主 agent 负责章节总量分配”。
- 已确认现状：风格实例目前主要服务于 `style_remix`，`fanfic` 尚未形成对等的实例加载与语义分流。
- 用户已确认采用“全量替换”方案：废弃旧 `mode` 语义，统一切换到“创作类型 + 篇幅层级”新结构，不保留旧任务创建链路上的旧字段作为主输入。
- 已生成实施计划文档：`docs/superpowers/plans/2026-04-21-task-mode-chat-model-full-replace.md`
- 已落地：后端主输入改为 `creative_mode`、`novel_size`、`chapter_word_min`，并保留内部 `mode` 兼容桥供旧工作流继续运行。
- 已落地：`StoryPlan` 增加 `planned_chapter_count`，`normalized_spec` 增加 `chapter_count_range`、`chapter_word_min`、`chapter_word_max`、`chapter_word_range_text`。
- 已落地：`fanfic` 与 `style_remix` 都支持加载实例，分别走 `canon_guidance` 与 `style_guidance`。
- 已落地：前端创建页改为“创作类型 + 篇幅规模 + 单章字数下限”，首页/运行页/归档页展示同步改为新语义。
- 已落地：聊天接口改为运行时解析默认模型，聊天页支持会话级模型选择并持久化。
- 已补充：默认聊天模型必须为网关可用模型，纯 `registry` 模型不再允许设为默认聊天模型。
