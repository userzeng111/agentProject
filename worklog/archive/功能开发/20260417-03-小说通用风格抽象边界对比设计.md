# 问题标题
小说通用风格抽象边界对比设计

# 用户原始诉求
只读对比 `NoteStyle/bisheng-style` 和当前项目现有小说任务流，站在“只做小说通用层、不考虑其他风格”的前提下，输出一个最小公共抽象：需要哪些对象、加载顺序、触发方式、运行时注入点。不要写实现，只给设计边界。

# 当前状态
进行中：已确认本任务为项目内只读设计分析，正在对比 `NoteStyle/bisheng-style` 的实例化风格结构与当前项目小说任务流中的风格装载与提示词注入链路，准备输出“小说通用层”的最小公共抽象边界。

# 当前结论
- `bisheng-style` 的稳定公共面不是整个 skill 生命周期，而是“实例注册表 + 实例清单 + 分维度规则文件 + 分阶段加载优先级”这一套小说风格运行资料结构。
- 当前项目小说任务流的稳定公共面不是前端选择器，而是 `TaskCreateRequest -> normalized_spec -> ContextManager instruction/context_packet -> StoryEngine prompt` 这一条运行时注入链路。
- 若只做“小说通用层”，最小公共抽象应聚焦为四类对象：
  - 风格源目录（style source）
  - 风格实例元数据（style profile manifest）
  - 分维度规则片段（rule sections）
  - 运行时风格载荷（runtime style payload）
- 最小公共抽象的加载顺序应为：
  - 发现实例注册表
  - 解析实例元数据
  - 装载规则文件
  - 编译为运行时摘要
  - 在任务归一化阶段挂入 `normalized_spec`
  - 在大纲/正文上下文构建与 `StoryEngine` prompt 渲染时消费
- 触发方式应限定在小说任务域内：
  - 显式模式触发：如 `style_remix`
  - 显式实例触发：传入 `style_profile_id`
  - 可选文本补充触发：用户额外填写 `style`
- 运行时注入点应限定为四处：
  - API/任务输入层：接收实例标识与补充要求
  - 任务归一化层：生成统一 `style_guidance`
  - 上下文装配层：进入 `outline/chapter` instruction 与 snapshot
  - LLM Prompt 层：大纲、章节、修订 prompt 消费统一风格约束
- 不应纳入本次“小说通用层”边界的内容：
  - skill 触发词路由器本身
  - 蒸馏/分析新风格流程
  - 非小说任务复用
  - 通用 Agent Skill 执行框架
  - 前端具体交互形态与多风格混合策略
