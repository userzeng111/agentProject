## 已确认问题

- 早期等待态存在竞争窗口：任务刚对外显示 `waiting_outline_review` 时，后台自动审核仍在运行，此时调用 `resume` 会返回 400“任务正在运行中，请勿重复提交。”，并可能留下部分 `resume/recovered` 事件痕迹。
- 中间阶段展示存在残留：任务实际处于 `drafting`、`verification`、`fix-issues` 时，workspace API 曾持续返回旧的 `pending_review_summary.review_type=outline_review`，摘要为“等待章节计划批次审核，已确认 0/4 章。”；完成后该摘要恢复正常。
- 阶段命名有歧义：章节窗口门禁和全文验证都使用 `verification` 相关阶段，页面上容易把章节门禁误读为最终全文验证。
- 真实模型输出触发过 JSON 解析失败：`chapter-window-gate` 首次验证出现 `model.response.parse_failed`，系统随后走 repair 并继续完成，说明内部容错链路有效，但前端/日志展示应更清楚。
