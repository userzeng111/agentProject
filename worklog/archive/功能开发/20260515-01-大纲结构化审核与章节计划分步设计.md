# 大纲结构化审核与章节计划分步设计

## 用户原始诉求

当前审核页面直接将 markdown 文本平铺展示，需要改造为支持按"世界观"、"人物"、"章节计划"等属性分级展开/跳转的结构化展示。

章节计划需支持在大纲总纲下分步迭代设计（类似正文分步编写）。特别是在长篇小说时，章节计划不能一次设计全，要先有一个大纲总纲，然后章节计划在大纲总纲存在的情况下分步设计。

用户可设置每批生成的章数，默认 20 章。

### 2026-05-16 修复：用户测试"功能没有成功"

**根本原因**：`resume_task` 中 master approval 和 batch approval（还有剩余）分支**没有调用 `_start_background`**，导致 LangGraph 工作流不会继续执行 `plan_chapter_batch` 节点。用户点击"通过"后任务状态变为 `chapter_batches`，但 `current_batch_plans` 始终为空，前端显示"正在生成下一批章节计划..."但后台从未执行。

**修复内容**：
1. `app/application/task_service/review.py`
   - master approval 分支：添加 `_record_last_action` + `_sync_supervisor_plan` + `_start_background` 调用
   - batch approval（还有剩余）分支：同步 checkpoint 中的 `outline_completed_count` / `outline_batch_index` / `outline_batch_retry_count` / `story_plan`，然后启动后台
   - batch approval（全部完成）分支：保持原逻辑，不启动后台，直接 `ready_for_batch`
2. `app/graph/nodes/outline.py`
   - `plan_chapter_batch` 节点：若 `story_plan.chapter_plan` 已存在且长度足够，直接切片复用，避免重复调用 LLM（兼容测试 FakeEngine）
3. `app/graph/utils/helpers.py`
   - `_normalize_story_plan`：优先保留已有的 `planned_chapter_count`，不再强制从 `chapter_plan` 长度推导（支持总纲生成完整 chapter_plan 但 batch 阶段仍按 planned_chapter_count 判断）
4. `tests/test_task_service_review_resume.py`
   - 更新测试期望：master approval 后应调用 `_start_background`

## 方案要点

### 两阶段审核

1. **大纲总纲审核**（`outline_phase="master"`）
   - 展示：世界观 + 人物 + 标题/梗概/预计总章数
   - `chapter_plan` 为空列表
   - 通过后进入章节计划批次生成

2. **章节计划批次审核**（`outline_phase="chapter_batches"`）
   - 总纲区折叠为只读（已锁定）
   - 章节计划区展示：已确认批次 + 当前待审批次
   - 每批默认 20 章，用户可配置批次大小
   - 通过且还有剩余 → 生成下一批
   - 通过且全部完成 → 进入 `ready_for_batch`
   - 驳回 → 重新生成本批
   - 支持回滚到任意已确认批次

### 存储轻量

- 不新增数据库表，不借用 `novel_outline_chapter`
- 进度只存 `StoryPlan.chapter_plan` 列表本身
- 批次状态通过 `ReviewPayload` 扩展字段携带
- 回滚通过列表截断实现

### 复用已有能力

- 正文批次模式语义（`continuation.py`）
- `ChapterPairReview` 的章节卡片样式
- `AgentTracePanel` 的折叠交互
- `resume_task` + `ReviewPayload` 审核链路
- `StepIndicator` 动态步骤展示
- `recovery.py` 恢复逻辑
