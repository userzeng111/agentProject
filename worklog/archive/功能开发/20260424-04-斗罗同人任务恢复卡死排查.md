# 问题标题
斗罗同人任务恢复卡死排查

# 用户原始诉求
用户反馈任务 `task_fa64bdc38c` 在创作时无法走通全流程，界面多次出现"任务当前无法恢复，缺少可恢复的稳定产物，已转入待人工处理"，但 `planning` 阶段已记录 `outline-history`。

要求排查并修复。

# 最终结论

## 根因
1. **恢复门禁过严**：`_should_attempt_recovery()` 仅对 `WAITING_OUTLINE_REVIEW / WAITING_CHAPTER_REVIEW / WAITING_VERIFICATION_REVIEW / PLANNING(outline*)` 打开恢复入口，`_can_recover_outline_review()` 仅接受 `WAITING_OUTLINE_REVIEW` 或 `PLANNING(outline*)`。当任务已转入 `waiting_manual_action` 且存在大纲历史时，被错误判定为不可恢复。
2. **叠加问题**：真实任务同时存在旧后台规划线程悬空与大纲 JSON 解析失败，导致状态进一步混乱。

## 修复内容
- `apps/agent-runtime/app/application/task_service/recovery.py`
  - 放宽 `_should_attempt_recovery()`，允许 `waiting_manual_action` 状态下存在可恢复产物时进入恢复流程。
  - 放宽 `_can_recover_outline_review()`，允许 `waiting_manual_action` 状态下通过 `outline-history.json` 存在性判断可恢复性。
  - 同步放宽 `_can_recover_chapter_review` 与 `_can_recover_verification_review`。
  - `_preview_recover_to_stable` 统一使用 `_can_recover_*` 方法。
- `apps/agent-runtime/tests/test_task_service_review_resume.py`
  - 新增 `waiting_manual_action + outline-history` 恢复到 `waiting_outline_review` 的回归测试。

## 验证
- 回归测试 `test_task_service_review_resume` 12 个测试全部通过。
- 与后续 runner.py / story_engine.py 的修复共同生效后，真实异常任务可正常恢复。
