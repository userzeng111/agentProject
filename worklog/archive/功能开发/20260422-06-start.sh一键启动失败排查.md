# 问题标题
start.sh 一键启动失败排查

## 用户原始诉求
继续修复启动问题，要求采用多 agent 并行推进，并恢复可用的前后端热更新运行态。

## 当前状态
已修复：
- `start.sh` 新增 `--detach` 后台模式，并支持通过环境变量覆盖 `BACKEND_HOST/BACKEND_PORT/FRONTEND_HOST/FRONTEND_PORT/RUNTIME_DIR`。
- 后台模式会为前后端写入独立日志和 pid 文件，健康检查通过后退出脚本。
- 已验证默认端口 `127.0.0.1:8000` / `127.0.0.1:3000` 可由 `./start.sh --detach` 正常拉起。

## 根因结论
- 应用本身没有启动问题：后端 `uvicorn --reload` 与前端 `next dev` 独立执行都可正常启动。
- 真正缺口在于原 `start.sh` 只适合前台托管子进程，缺少真正的 detached 启动模式；当父 shell 退出时，后台子进程无法稳定保活。
- 现在脚本已补齐 detached 模式，由脚本内部负责后台化、日志落盘、pid 落盘和健康检查。

- 修复脚本后重新验证：前后端监听、健康检查、首页可访问。已完成
