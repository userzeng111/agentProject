# 系统代码 review 与里程碑重构

## 用户原始诉求
review codex 编写的系统代码，修复安全、架构与稳定性问题，并进行里程碑式重构。要求 DRY、可观测性优先、所有特性保持可用。

## 解决方案（M1-M5）

### M1 安全与健壮性
- `sqlite_store.py` / `vector_utils.py`：表名/标识符白名单正则校验，消除 SQL 注入
- `chunking.py`：`chunk_overlap >= chunk_size` 前置校验
- `llama_cpp_generator.py`：`stop_tokens` 参数防止无限生成
- `llama_cpp_embedder.py`：per-item 重试 + 详细日志
- `gateway_client.py` / `base.py`：JSON 截断修复与重试机制

### M2 可观测性层
- 新建 `app/observability/`：结构化日志（request_id/task_id 追踪）、TracingMiddleware、LLM 指标（latency histogram + counter）
- `gateway_client.py` 全路径集成 metrics + 日志
- `main.py` 注册 `TracingMiddleware`

### M3 架构解耦
- `cli.py` 拆分为 argparse 入口 + `IndexEngine` 业务类
- `main_graph.py` 拆分为 nodes/routers/utils/state/checkpointer 子模块
- 新增 `app/graph/state.py` 解耦 `WorkflowState` 循环导入

### M4 前端稳定性
- `api.ts`：超时 + 重试 + 错误解析
- `chat-client.tsx`：函数式状态更新 + `hasInitializedRef`
- `task-run-client.tsx`：EventSource 自动重连
- `chat-storage.ts`：`crypto.randomUUID()`

### M5 测试与CI
- `fakes.py` 提取共享 Fake 类
- `datetime.UTC` 全局污染修复
- `.github/workflows/ci.yml` 三任务并行
- `pyproject.toml` ruff/mypy 配置
