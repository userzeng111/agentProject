## 当前已确认的核定结果

### 与当前代码基本一致的部分

- `apps/agent-runtime/app/graph/main_graph.py` 当前确实存在 7 个主要节点：
  - `normalize_request`
  - `prepare_outline_context`
  - `plan_story`
  - `review_outline`
  - `prepare_draft_context`
  - `draft_story`
  - `cancel_task`
- `review_outline` 的人工审核中断确实通过 `langgraph.types.interrupt` 实现。
- 图编译时确实挂载了 `MemorySaver()` 作为 checkpointer。
- `StoryEngine` 当前确实维护了章节生成过程中的 `conversation_history`，且模型响应缓存 key 基于 `model + messages` 的稳定 JSON 哈希生成。
- `TaskService` 当前确实通过后台线程、事件记录与 SSE 流把任务进展推给前端工作台。

### 已发现需要修正或降级表述的部分

- 文档把 LangGraph 节点描述为“纯函数、无副作用”并不准确；当前节点会调用上下文管理器、模型网关和人工中断机制，属于“返回状态增量的工作流节点”，但不是严格意义上的纯函数。
- 文档把 `route_after_review` 描述为“通过后进入 `draft_story`”，这只是路由标签；当前真实图边是先进入 `prepare_draft_context`，再进入 `draft_story`。
- 文档中恢复节点示例返回字段写作 `comment`，而当前 `WorkflowState` 实际字段名是 `review_comment`。
- 文档第 5 章把重试算法写成“指数退避”，但当前 `apps/agent-runtime/app/llm/gateway_client.py` 实现是 `1.5 * (attempt + 1)`，属于线性递增等待，不是指数退避。
- 文档第 6 章里 `conversation_history` 的示意只保留了 `assistant` 消息，这与当前实现不完全一致；真实历史会保留第一轮请求消息，并在后续轮次形成“历史消息 + 当前 user + 新 assistant”的链。
- 文档中关于“价格”“具体模型窗口数值”“跨供应商兼容程度”的部分带有时效性或静态注册表假设，扩写时更适合改为“当前项目内注册值/示例值”，避免写成厂商官方保证。
