# 审核流程重构

## 用户原始诉求
1. 大纲审核支持打回：用户给出建议后，携带上下文优化大纲，循环直到通过
2. 正文以两章为锚点：基于大纲编写两章后交用户审核，不通过则修复，通过后继续下一对
3. 全部完成后流图验证：整体验证一致性，用户审核验证结果

## 设计方案（已审核通过）

### 大纲审核循环
- plan_story → review_outline → 不通过 → revise_outline（携带意见+原大纲→LLM重新生成）→ 重新 review_outline
- 循环直到用户通过

### 章节对锚点
- batch_index 指向当前章节对（0, 2, 4...）
- draft_chapter_pair 生成两章 → review_chapter_pair 用户审核
- 不通过 → revise_chapter_pair 修复 → 重新审核
- 通过 → batch_index += 2，回到 prepare_chapter_pair_context
- 最后一对可能只有 1 章

### 全文验证
- verify_full_story → review_verification 用户审核报告
- 不通过 → fix_verified_issues 修复 → 重新验证
- 通过 → assemble_result → END
