# 夜半回廊归档任务流异常复核

## 用户原始诉求
夜半回廊的这个归档内容，在执行现在的任务流时存在很多问题，很多任务流流程执行异常，没有实现联通的功能，导致无法成功完成整个任务，需要修复这个问题。

## 当前已知上下文
- 已定位到归档任务：`tasklog/archive/task_f4d242fc2b`
- 归档标题：`夜半回廊`
- 当前需要先复核归档产物、状态流转、任务流实现与前后端联通点

## 当前排查结论
- 该归档任务的大纲包含 5 章，但最终 `result.json` 与 `result.md` 只包含前 2 章，属于真实流程提前结束，不是前端展示错误
- 事件流显示：第 1-2 章审核通过后，没有继续进入下一对章节生成，而是直接进入 `waiting_verification_review`，随后完成归档
- 根因集中在 `apps/agent-runtime/app/graph/main_graph.py`
  - `prepare_chapter_pair_context(...)` 会返回 `total_chapters` 与 `completed_count`
  - 但 `WorkflowState` 中未声明这两个字段
  - `route_after_accumulate(...)` 依赖 `state.get("total_chapters", 0)` 判断是否继续下一对章节
  - 结果状态里取不到真实 `total_chapters`，默认成 `0`，导致流程在累计完第一对章节后直接跳转到 `verify_full_story`

## 拟定修复方向
- 补齐 `WorkflowState` 缺失的章节对流程状态字段，确保章节总数和已完成数在图状态中可持续传递
- 为该回归补充自动化测试，覆盖“5 章大纲应依次生成 3 轮章节对后再进入验证”的场景
- 复核 `夜半回廊` 这类旧归档是否需要额外提供重跑/修复策略
