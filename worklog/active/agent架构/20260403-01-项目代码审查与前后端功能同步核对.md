# 项目代码审查与前后端功能同步核对

## 用户原始诉求
采用 agent team 模式分配任务：
- 进行 code review
- 分析项目存在的问题
- 检查前后端页面功能是否同步
- 记录功能是否实现完毕

## 当前已知上下文
- 当前仓库同时包含前端 `apps/web` 与后端 `apps/agent-runtime`
- 共享协议位于 `packages/shared-schema`
- 用户要求采用 agent team 模式并行分析

## 当前状态
- 已创建问题记录
- 正在进行并行代码审查与前后端功能对齐核对

## 本轮计划
- 梳理前端页面、功能入口与调用链
- 梳理后端 API、任务流与状态模型
- 交叉核对页面展示、接口返回、状态语义是否一致
- 汇总缺失功能、不同步项与完成度结论

## 当前评审结论

### 总体判断
- 当前仓库的主链路能力已经具备：创建任务、运行、三类审核、结果页、自动归档、归档列表与归档详情都已有实现。
- 但“前后端页面功能是否同步”只能判定为**部分同步**，主要问题不在于完全没有页面，而在于：
  - 前端页面已展示，但后端字段没有完整兑现；
  - 后端接口已支持，但前端入口/错误态/动作覆盖不完整；
  - 共享协议包已明显落后于真实接口，联调一致性主要靠人工维护。

### 关键问题分级

#### P0 / 严重
- 前端默认 API 地址与 README 启动说明不一致：
  - 前端默认走 `http://127.0.0.1:8000`
  - README 后端启动为 `http://127.0.0.1:8001`
  - 结果是开箱即用场景下前端会直接连错端口。
- 前端多个详情页存在“错误时假加载”问题：
  - `/tasks/[id]`
  - `/review/[id]`
  - `/result/[id]`
  - `/archive/[id]`
  - 首次请求失败时只记录错误，不会真正渲染错误态，用户会一直看到“正在读取”。
- 后端暴露了任务级 `auto_review` 字段，但实际执行并未按任务粒度生效：
  - `POST /api/tasks` 可提交 `auto_review`
  - `TaskRecord` 也有 `auto_review`
  - 但创建任务时未写入该字段，运行时实际使用的是服务级全局配置。
- 后端状态/流程语义里存在死分支：
  - `cancelled`
  - `waiting_manual_action`
  - `assembling`
  - 枚举、dashboard 与 SSE 仍暴露这些状态，但主图当前不可达。

#### P1 / 高
- 工作台页只给 `waiting_outline_review` 显示“进入审核”，没有覆盖：
  - `waiting_chapter_review`
  - `waiting_verification_review`
  - 导致从任务页继续走章节审核/验证审核时入口缺失。
- 共享协议包 `packages/shared-schema` 已明显过期：
  - `TaskStatus` 只剩极小子集
  - review/result/archive/workspace 等核心协议完全没有被共享包约束
  - 目前真实协议分别维护在前端本地类型与后端模型里。
- 大纲审核轮次 `revision_count` 在工作流中存在，但没有从后端 review 接口透出给前端，审核页只能通过类型断言猜测轮次。
- `/api/tasks/{id}/review` 在没有 `pending_review` 但已有历史审核时，会统一伪装成 `outline_review`，会误导前端对最后审核节点类型的判断。

#### P2 / 中
- `archive list` 前端类型声明了 `entry_refs`，但 API 实际不返回。
- `artifact_index.json_ref` 在前端类型中存在，但结果/归档接口实际不会返回。
- `archive detail` 前端类型与后端真实响应不一致：
  - 前端多声明了 `context_status/context_snapshot`
  - 后端实际返回了 `sources`
- 工作台上下文状态与后端真实落盘不完全一致：
  - 前端会消费 drafting 阶段上下文状态
  - 但后端当前主要只稳定持久化了 planning 快照。
- 首页“待处理”语义和后端 continue 列表不完全一致，后端把 `cancelled` 也放进了 continue 区。

#### P3 / 低
- 工作台页同时尝试 4 个 SSE 路径，说明事件流接口契约仍不稳定。
- 结果页与归档详情页虽然展示了 `md_ref/json_ref`，但没有提供直接点击查看或展开能力。
- 前端 lint 脚本当前不可直接用于校验：执行 `npm --prefix apps/web run lint` 会进入交互式初始化，而不是直接跑检查。

### 前后端同步结论
- 已同步：
  - 任务创建主链路
  - 三类审核主体数据：`outline/chapter_pair/verification`
  - 结果页主体数据：`result_summary/result_markdown/chapter_index/history_index`
  - 归档详情主体数据
  - `review_history` 主动作链：`waiting/submitted/rejected/repairing/approved`
- 部分同步：
  - 工作台动作入口
  - 审核轮次字段
  - 工件引用字段
  - 归档列表辅助引用字段
  - 上下文状态细节
  - 共享 schema
- 未同步或未真正实现：
  - 任务级 `auto_review`
  - 可达的 `cancelled/waiting_manual_action/assembling` 流程
  - 章节审核/验证审核从工作台直接继续的完整入口
  - 结果/归档页对引用文件的直接查看能力

### 页面与功能完成度
- 首页 `/`
  - 已实现基础任务列表、状态跳转、默认模型切换
  - 部分完成：统计与状态语义仍受后端 continue/running 划分影响
- 创建页 `/create`
  - 已实现基础创建、模型选择、素材上传
  - 未覆盖：`auto_review` 配置入口
- 工作台 `/tasks/[id]`
  - 已实现运行、日志、章节进度、章节预览
  - 部分完成：审核入口覆盖不全，错误态缺失，状态展示有硬编码推断
- 审核页 `/review/[id]`
  - 已实现三类审核 UI、提交通过/驳回、自动审核轨迹展示
  - 部分完成：大纲轮次字段缺失，部分文案与真实阶段不一致
- 结果页 `/result/[id]`
  - 已实现结果摘要、正文、章节索引、工件索引、历史记录
  - 部分完成：引用仅展示字符串，错误态缺失
- 归档列表 `/archive`
  - 已实现分页与详情跳转
- 归档详情 `/archive/[id]`
  - 已实现请求摘要、正文、过程摘要流、章节索引、事件尾流
  - 部分完成：类型与真实响应不完全一致，引用只展示不消费

### 完成度判断
- 核心联调完成度可估计为 `75%` 左右。
- 原因：
  - 主功能链路多数已落地；
  - 但协议单一事实源失效；
  - 多个字段/状态/动作仍存在“页面已做，契约未收口”或“后端已做，前端未补齐”的问题。
