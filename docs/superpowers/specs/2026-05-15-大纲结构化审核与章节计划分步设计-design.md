# 大纲结构化审核与章节计划分步设计

## 日期
2026-05-15

## 背景

当前审核页面（`task-review-client.tsx` 的 `OutlineReview`）将大纲内容以平铺 markdown 文本形式展示，用户无法按"世界观"、"人物"、"章节计划"等属性分级查看。对于长篇小说（如 400 章），LLM 一次性生成完整章节计划存在质量衰减和上下文溢出问题。需要引入"大纲总纲先行确认 + 章节计划分步迭代"的机制。

## 目标

1. 审核页面支持按世界观、人物、章节计划分级展开/折叠
2. 大纲总纲（世界观 + 人物 + 标题/梗概/总章数）先生成并确认
3. 章节计划在大纲总纲确认后分步生成，每批默认 20 章，用户可配置
4. 支持通过、驳回、回滚到任意已确认批次
5. 新增 `novel_chapter_plan_batch` 表跟踪章节计划批次状态，与正文分步模式对齐

## 非目标

- 世界观和人物本身不分步生成（一次性在总纲阶段完成）
- 不改造正文分步编写（`drafting` 阶段）的逻辑
- 不新增 `TaskStatus` 枚举
- 不修改 `StoryPlan` 领域模型结构（`chapter_plan` 仍作为内存/JSON 承载）
- 总纲阶段（master）不写入 `novel_outline_chapter`，仅章节计划批次生成时写入

## 架构设计

### 审核阶段划分

| 阶段 | `outline_phase` | 内容 | 用户操作 |
|------|-----------------|------|----------|
| 总纲审核 | `master` | 世界观 + 人物 + 标题/梗概/总章数 | 通过 / 驳回 |
| 批次审核 | `chapter_batches` | 已确认批次(只读) + 当前待审批次 | 通过 / 驳回 / 回滚 |

两阶段共享同一个 `TaskStatus.WAITING_OUTLINE_REVIEW`，通过 `ReviewPayload.outline_batch.phase` 区分语义。

### 状态流转

```
planning
   │
   ▼
waiting_outline_review (outline_batch.phase=master)
   │   • story_plan.chapter_plan = []
   │   • 前端展示：世界观、人物、总纲信息
   │
   ├── 驳回 ──► revise_outline ──► 回到 waiting_outline_review(master)
   │
   └── 通过 ──► plan_chapter_batch(outline_batch_index=0, outline_batch_size=N)
                    │   • LLM 生成第 1 批 ChapterPlan
                    │   • 注入总纲作为上下文
                    ▼
       waiting_outline_review (outline_batch.phase=chapter_batches)
                    │   • 前端展示：总纲(折叠只读) + 已确认批次 + 当前批次
                    │
                    ├── 驳回 ──► plan_chapter_batch 重新生成本批 ──► 回到 waiting_outline_review(chapter_batches)
                    │
                    ├── 通过且 outline_completed + outline_batch_size < outline_total
                    │   └── 生成下一批 ──► 回到 waiting_outline_review(chapter_batches)
                    │
                    └── 通过且全部完成
                        └── ready_for_batch ──► 正文编写
```

### 回滚机制

回滚通过数据库事务实现：

```python
def rollback_chapter_plan_batches(
    task_id: str,
    batch_size: int,
    keep_batch_count: int,
) -> None:
    keep_count = keep_batch_count * batch_size

    # 1. 删除被回滚批次的 novel_outline_chapter 记录
    delete_outline_chapters_after(task_id, keep_count)

    # 2. 将被回滚批次状态设为 rejected
    mark_chapter_plan_batches_rejected_after(task_id, keep_batch_count)

    # 3. 截断 story_plan.chapter_plan（内存+JSON 同步）
    story_plan.chapter_plan = story_plan.chapter_plan[:keep_count]
```

回滚后，`outline_batch_index` 重置为 `keep_count`，重新生成被截断的批次。

#### `novel_outline_chapter` 表扩展

```python
class NovelOutlineChapterModel(Base):

```

**`status` 字段语义隔离**：
- 计划阶段枚举：`outline_planned`（刚写入）、`outline_waiting_review`（等待审核）、`outline_approved`（计划通过）
- 正文阶段枚举：`drafted`（已起草）、`approved`（已审核通过）
- 总纲阶段（master）不写入 `novel_outline_chapter`，仅章节计划批次生成时才写入，确保两阶段状态语义不重叠

`novel_chapter_plan_batch` 状态流转：
- `planned`：批次刚创建
- `waiting_review`：批次生成完成，等待审核
- `approved`：审核通过
- `rejected`：审核驳回或回滚

`novel_outline_chapter` 计划阶段状态（与正文阶段隔离）：
- `outline_planned`：章节计划刚写入
- `outline_waiting_review`：批次生成完成，等待审核
- `outline_approved`：章节计划审核通过（进入正文编写前）

#### 新增 `plan_chapter_batch` 节点

```python
def plan_chapter_batch(
    state: WorkflowState,
    *,
    engine: Any,
    default_batch_size: int = 20,
) -> WorkflowState:
    story_plan_dict = state.get("story_plan") or {}
    batch_index = state.get("outline_batch_index", 0)
    batch_size = state.get("outline_batch_size", default_batch_size)
    total = story_plan_dict.get("planned_chapter_count", 0)

    effective_size = min(batch_size, max(total - batch_index, 0))
    if effective_size <= 0:
        return {"current_batch_chapter_plans": []}

    batch_plans = engine.build_chapter_plan_batch(
        spec=state["normalized_spec"],
        story_plan=story_plan_dict,
        batch_index=batch_index,
        batch_size=effective_size,
        confirmed_chapter_plans=story_plan_dict.get("chapter_plan", []),
        model=state["normalized_spec"].get("model_id"),
    )
    return {
        "current_batch_chapter_plans": [p.model_dump(mode="json") for p in batch_plans],
        # 注意：不覆盖 outline_batch_size，保持用户原始配置
        "outline_batch_retry_count": state.get("outline_batch_retry_count", 0) + 1,
    }
```

Prompt 设计要点：
- 注入总纲（世界观、人物、标题、梗概）
- 注入已确认章节的标题列表（作为连贯性约束）
- 明确要求只生成指定范围（如第 21-40 章）的 `number/title/goal`

批次入库：

```python
def plan_chapter_batch(...) -> WorkflowState:
    # ... 生成批次 ...

    # 创建批次记录 + 章节计划入库（同一事务）
    batch_no = (batch_index // batch_size) + 1
    with db_transaction() as session:
        create_chapter_plan_batch(
            task_id=state["task_id"],
            batch_no=batch_no,
            start_chapter=batch_index + 1,
            end_chapter=batch_index + effective_size,
            requested_count=batch_size,
            effective_count=effective_size,
            status="waiting_review",
            session=session,
        )

        # upsert_outline_chapter_plan 实现：
        # 1. DELETE FROM novel_outline_chapter WHERE task_id=? AND chapter_number=?
        # 2. INSERT INTO novel_outline_chapter (...) VALUES (...)
        # 步骤 1 确保同一章号在驳回重新生成时不残留旧记录
        for plan in batch_plans:
            upsert_outline_chapter_plan(
                task_id=state["task_id"],
                chapter_number=plan.number,
                title=plan.title,
                goal=plan.goal,
                outline_batch_no=batch_no,
                status="outline_planned",
                session=session,
            )

    return {
        "current_batch_chapter_plans": [p.model_dump(mode="json") for p in batch_plans],
        "outline_batch_retry_count": state.get("outline_batch_retry_count", 0) + 1,
    }
```

### 2. `app/graph/routers/review.py`

`route_after_outline_review` 按 `outline_phase` 分支：

```python
MAX_BATCH_RETRIES = 3

def route_after_outline_review(state: WorkflowState) -> str:
    if state.get("cancelled"):
        return "cancel_task"
    if state.get("approved"):
        phase = state.get("outline_phase", "master")
        if phase == "master":
            return "plan_chapter_batch"
        # chapter_batches 阶段：判断是否全部完成
        batch_index = state.get("outline_batch_index", 0)
        batch_size = state.get("outline_batch_size", 20)
        total = state.get("outline_total_count", 0)
        if batch_index + batch_size >= total:
            return "prepare_chapter_pair_context"  # 全部完成，进正文
        return "plan_chapter_batch"  # 继续下一批
    # 驳回分支
    phase = state.get("outline_phase", "master")
    if phase == "chapter_batches":
        retry = state.get("outline_batch_retry_count", 0)
        if retry >= MAX_BATCH_RETRIES:
            # 重试超限，退回总纲修订
            return "revise_outline"
        return "plan_chapter_batch"  # 重新生成本批
    if state.get("outline_revision_count", 0) >= MAX_OUTLINE_REVISIONS:
        return "prepare_chapter_pair_context"
    return "revise_outline"
```

### 4. `app/application/task_service/review.py`

`resume_task` 中 `outline_review` 分支扩展：

```python
if review_type == "outline_review" and approved:
    story_plan = task.story_plan or task.pending_review.story_plan
    if story_plan is None:
        raise ValueError("当前任务缺少大纲，无法进入继续创作阶段。")

    outline_batch = task.pending_review.outline_batch
    phase = outline_batch.phase if outline_batch else "master"

    if phase == "master":
        # 总纲通过，进入章节计划批次生成
        task.story_plan = story_plan
        self._ensure_novel_project_seeded(task)
        # 初始化批次参数
        task.pending_review.outline_batch = OutlineBatchInfo(
            phase="chapter_batches",
            completed_count=0,
            batch_index=0,
            batch_size=outline_batch.batch_size if outline_batch else 20,
            total_count=story_plan.planned_chapter_count or 0,
        )
        self.store.save(task)
        snapshot = self.store.set_waiting_outline_review(task_id, task.pending_review)
        return self._safe_sync_supervisor_plan(task_id, fallback=snapshot)

    else:
        # 章节计划批次通过
        batch_plans = outline_batch.current_batch_plans if outline_batch else []
        story_plan.chapter_plan.extend(batch_plans)
        completed = len(story_plan.chapter_plan)
        task.story_plan = story_plan

        total = story_plan.planned_chapter_count or completed
        batch_size = outline_batch.batch_size if outline_batch else 20

        # 更新数据库批次状态（同一事务内完成）
        batch_no = (outline_batch.batch_index // batch_size) + 1 if outline_batch else 1
        with db_transaction() as session:
            mark_chapter_plan_batch_approved(task_id, batch_no, session=session)
            for plan in batch_plans:
                mark_outline_chapter_plan_approved(task_id, plan.number, session=session)

        if completed >= total:
            # 全部完成，进入 ready_for_batch
            self.store.save(task)
            snapshot = self.store.set_ready_for_batch(
                task_id, story_plan,
                message=comment.strip() or f"章节计划全部完成（{completed}章），等待继续创作。"
            )
            return self._safe_sync_supervisor_plan(task_id, fallback=snapshot)

        # 还有剩余，准备下一批
        outline_batch.completed_count = completed
        outline_batch.batch_index = completed
        outline_batch.current_batch_plans = []
        outline_batch.retry_count = 0  # 新批次重置重试计数
        self.store.save(task)
        snapshot = self.store.set_waiting_outline_review(task_id, task.pending_review)
        return self._safe_sync_supervisor_plan(task_id, fallback=snapshot)
```

### 5. `app/application/task_service/review.py` — 驳回与回滚

驳回时重新生成本批：

批次驳回不进入 `revise_outline`，而是保持 `outline_batch.phase="chapter_batches"` 并清空 `current_batch_plans`，由工作流重新执行 `plan_chapter_batch`：

```python
if review_type == "outline_review" and not approved:
    outline_batch = task.pending_review.outline_batch if task.pending_review else None
    if outline_batch is None:
        outline_batch = OutlineBatchInfo(phase="master")
        task.pending_review.outline_batch = outline_batch
    phase = outline_batch.phase
    if phase == "master":
        # 原有逻辑：进入 revise_outline
        snapshot = self.store.mark_stage(
            task_id,
            status=TaskStatus.DRAFTING if approved else TaskStatus.PLANNING,
            stage="drafting" if approved else "planning",
            progress=60 if approved else max(task.progress, 56),
            message=comment.strip() or ("人工审核已通过，任务转入后台处理。" if approved else "人工审核已驳回，正在修订大纲。"),
            event_type="review.submitted",
            unit_id="outline",
        )
    else:
        # 批次驳回：清空当前批次，保留已确认的 chapter_plan，重新生成
        batch_size = outline_batch.batch_size if outline_batch else 20
        batch_no = (outline_batch.batch_index // batch_size) + 1 if outline_batch else 1
        with db_transaction() as session:
            mark_chapter_plan_batch_rejected(task_id, batch_no, session=session)
            # 删除当前待审批次的 outline_chapter 记录（重新生成时会 upsert）
            delete_outline_chapter_plans_by_batch(task_id, batch_no, session=session)
            outline_batch.current_batch_plans = []
            self.store.save(task, session=session)
            snapshot = self.store.set_waiting_outline_review(task_id, task.pending_review, session=session)
    snapshot = self._record_last_action(task_id, model_id=action_model_id, kind="resume")
    snapshot = self._sync_supervisor_plan(task_id)
    self._start_background(task_id, self._resume_task_sync, task_id, approved, comment, action_model_id)
    return snapshot
```

批次驳回后 `_resume_task_sync` 的恢复逻辑：
- 通过 `Command(resume={"approved": False, ...})` 恢复工作流
- `route_after_outline_review` 在 `approved=False` 且 `outline_phase="chapter_batches"` 时返回 `"revise_outline"`
- 但 `revise_outline` 节点需改造：当 `outline_phase="chapter_batches"` 时，不执行总纲修订，而是直接透传状态（保持 `batch_index` 不变），让工作流自然回到 `review_outline`
- 或者更简洁：在 `route_after_outline_review` 中，当 `approved=False` 且 `outline_phase="chapter_batches"` 时直接返回 `"plan_chapter_batch"`，跳过 `revise_outline`

回滚接口（新增，带并发控制）：

```python
def rollback_chapter_plan(self, task_id: str, keep_batch_count: int) -> TaskRecord:
    with self._run_lock:
        if task_id in self._active_runs:
            raise ValueError("任务正在后台运行中，请等待完成后再操作回滚。")

        task = self.store.get(task_id)

        if task.status is not TaskStatus.WAITING_OUTLINE_REVIEW:
            raise ValueError(f"当前任务状态为 {task.status.value}，不支持回滚操作。")

        story_plan = task.story_plan
        if not story_plan or not story_plan.chapter_plan:
            raise ValueError("当前没有可回滚的章节计划。")

        outline_batch = task.pending_review.outline_batch if task.pending_review else None
        batch_size = outline_batch.batch_size if outline_batch else 20
        keep_count = keep_batch_count * batch_size

        if keep_count >= len(story_plan.chapter_plan):
            raise ValueError("回滚位置必须早于当前进度。")

        current_confirmed = outline_batch.completed_count if outline_batch else 0
        if keep_count == current_confirmed and not (outline_batch.current_batch_plans if outline_batch else []):
            return task

        # 数据库 + JSON 同一事务回滚
        with db_transaction() as session:
            # 1. 删除被回滚的章节计划记录
            delete_outline_chapter_plans_after(task_id, keep_count, session=session)
            # 2. 将被回滚批次状态设为 rejected
            mark_chapter_plan_batches_rejected_after(task_id, keep_batch_count, session=session)
            # 3. 内存/JSON 截断
            story_plan.chapter_plan = story_plan.chapter_plan[:keep_count]
            task.story_plan = story_plan
            if outline_batch:
                outline_batch.completed_count = keep_count
                outline_batch.batch_index = keep_count
                outline_batch.current_batch_plans = []
            # 4. 统一持久化（task_store.save 使用同一 session）
            self.store.save(task, session=session)
            snapshot = self.store.set_waiting_outline_review(task_id, task.pending_review, session=session)

        return snapshot
```

### 6. `app/application/task_service/recovery.py` — `_resume_seed_state` 适配

在恢复 `outline_review` 类型的中断任务时，从 `task.pending_review.outline_batch` 注入批次状态，避免恢复后回退到 `master` 阶段。若 `outline_batch` 信息不完整，从数据库 `novel_chapter_plan_batch` 重建：

```python
def _resume_seed_state(self, task, action_model_id=None):
    seed = self._initial_state(task, action_model_id)
    if task.story_plan is not None:
        seed["story_plan"] = task.story_plan.model_dump(mode="json")

    review = task.pending_review
    if review and review.type == "outline_review":
        outline_batch = review.outline_batch
        if outline_batch:
            seed["outline_phase"] = outline_batch.phase or "master"
            seed["outline_completed_count"] = outline_batch.completed_count or 0
            seed["outline_batch_index"] = outline_batch.batch_index or 0
            seed["outline_batch_size"] = outline_batch.batch_size or 20
            seed["outline_total_count"] = outline_batch.total_count or 0
            seed["outline_batch_retry_count"] = outline_batch.retry_count or 0
            plans = outline_batch.current_batch_plans or []
            seed["current_batch_chapter_plans"] = [
                p.model_dump(mode="json") if isinstance(p, ChapterPlan) else p for p in plans
            ]
        else:
            # 从数据库重建批次状态
            # batch_size 来源：取该任务所有已批准批次中最常见的 requested_count
            # （用户配置一次确定后不再变更，因此所有批次 requested_count 应一致）
            from app.storage.db_repository import get_chapter_plan_batch_summary
            summary = get_chapter_plan_batch_summary(task.id)
            if summary:
                seed["outline_phase"] = "chapter_batches"
                seed["outline_completed_count"] = summary["approved_count"]
                seed["outline_batch_index"] = summary["approved_count"]
                seed["outline_batch_size"] = summary["batch_size"]  # 由 approved 批次的 requested_count 推断
                seed["outline_total_count"] = summary["total_count"]
        seed["outline_revision_count"] = review.revision_count or 0

    # ... 其他 review 类型的恢复逻辑 ...
    return seed, entry_point
```

```python
def _outline_markdown(self, story_plan: StoryPlan, *, pending_batch: list[ChapterPlan] | None = None) -> str:
    lines = [
        f"# {story_plan.working_title}",
        "",
        story_plan.logline,
        "",
        "## 世界观",
        "",
    ]
    lines.extend(f"- {item}" for item in story_plan.world_notes)
    lines.extend(["", "## 人物", ""])
    lines.extend(f"- {item}" for item in story_plan.character_notes)

    confirmed = story_plan.chapter_plan or []
    lines.extend(["", f"## 章节计划（已确认 {len(confirmed)} / {story_plan.planned_chapter_count or '?'} 章）", ""])

    for chapter in confirmed:
        lines.append(f"- [已确认] 第{chapter.number}章 {chapter.title}：{chapter.goal}")

    if pending_batch:
        lines.append("")
        lines.append(f"### 待审核批次（第 {pending_batch[0].number}-{pending_batch[-1].number} 章）")
        lines.append("")
        for chapter in pending_batch:
            lines.append(f"- [待审核] 第{chapter.number}章 {chapter.title}：{chapter.goal}")

    return "\n".join(lines) + "\n"
```

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| LLM 生成的批次间章节计划衔接断裂 | Prompt 注入已确认批次的标题列表作为上下文约束 |
| 回滚后重新生成的批次风格不一致 | Prompt 注入完整总纲 + 已确认批次的 `title:goal` 列表 |
| 前端 `OutlineReview` 组件过度膨胀 | 拆分为 `MasterOutlineSection` / `ConfirmedBatchesSection` / `PendingBatchSection` |
| 用户误操作回滚导致大量工作丢失 | 回滚前弹窗确认，显示将丢失的章节范围 |
| 总纲阶段的 `planned_chapter_count` 估算偏差 | 允许用户在审核页微调总章数（前端 editable） |
