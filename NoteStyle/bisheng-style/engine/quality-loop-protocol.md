# 质量闭环自动化协议

## 环A：实例验证闭环

```
蒸馏 → 编译 → 静态检查 → 验证不通过 → 回修 → 重新编译 → 静态检查 → ... → 通过 → 注册为active
```

### 流程说明

1. 执行蒸馏流程（按 `distillation-playbook.md` 第1-6步）。
2. 编译为实例产物。
3. 执行静态检查项清单（见下文）。
4. 如有不通过项，按自动回修映射进行修复后重新编译。
5. 静态检查全部通过后，执行生成检查项（见下文）。
6. 生成检查全部通过后，由人工确认注册为 `active` 状态。

## 环B：创作质量闭环

```
生成 → 自检 → 修正 → 快照更新
```

### 流程说明

1. 基于active实例的rules生成小说内容。
2. 生成后立即执行自检：逐条对照rules中的Guardrail条款检查。
3. 发现违规项则自动修正并重新检查。
4. 每次成功的生成-自检-修正循环完成后，更新实例的快照数据（保真度评分、违规率等）。
5. 当快照数据显示连续N次保真度下降时，触发实例重新验证（回到环A）。

## 静态检查项清单

以下检查项在编译完成后、注册为active之前执行，不涉及实际文本生成。

| 编号 | 检查项 | 通过标准 | 检查方法 |
|------|--------|---------|---------|
| S1 | Schema完整性 | 所有rules文件按模板结构填写，无空缺必填段落 | 逐文件对照模板结构校验 |
| S2 | 证据链 | 每条规则至少有1条来自蒸馏产物的证据支撑 | 检查每条规则的溯源标注 |
| S3 | Guardrail可执行性 | 所有约束条款可直接执行，无需二次解读 | 人工审阅或自动化断言检查 |
| S4 | manifest完整性 | manifest.yaml所有必填字段已填写，无空值 | YAML字段校验 |
| S5 | fidelity_score | 保真度评分 >= 75 | 计算评分（基于证据密度、规则覆盖率、一致性） |
| S6 | 编译映射覆盖 | 12个蒸馏产物全部被映射到至少1个实例产物 | 对照 `compilation-map.md` 逐一检查 |

## 生成检查项清单

以下检查项在静态检查通过后，通过实际生成文本来验证。

| 编号 | 检查项 | 通过标准 | 检查方法 |
|------|--------|---------|---------|
| G1 | 单场景复现 | 单个场景的风格复现度 >= 70% | 生成单场景文本，与原文对比评分 |
| G2 | 单章保真度 | 单章生成文本的保真度评分 >= 75 | 生成完整章节，综合评分 |
| G3 | 三章稳定性 | 连续生成3章的保真度标准差 < 1.5 | 生成3章后计算标准差 |
| G4 | 负例拦截 | 对抗性提示（与风格矛盾的指令）的拦截率 >= 80% | 构造负例提示，检查是否被Guardrail拦截 |

## 自动回修映射

| 失败类型 | 触发条件 | 修复动作 |
|---------|---------|---------|
| Schema缺失 | S1不通过 | 从模板复制缺失段落，标记为"待填充"，返回蒸馏第5步补充 |
| 证据断裂 | S2不通过 | 返回蒸馏第3步，针对缺失证据的维度重新采集原文 |
| Guardrail模糊 | S3不通过 | 将模糊约束重写为可执行断言格式（if-then规则），返回蒸馏第6步重新编译 |
| manifest字段缺失 | S4不通过 | 补充缺失字段的默认值或从蒸馏数据中提取，重新校验 |
| 保真度不足 | S5或G1/G2不通过 | 分析低分维度，返回蒸馏第5步强化该维度的提炼，重新编译 |
| 稳定性不足 | G3不通过 | 检查rules中是否存在互相矛盾的条款，消除冲突后重新编译 |
| 负例泄露 | G4不通过 | 增强Guardrail约束，补充负例到规则中作为"禁止模式"，重新编译 |
| 映射遗漏 | S6不通过 | 检查遗漏的蒸馏产物，按 `compilation-map.md` 补充映射关系，重新编译 |
