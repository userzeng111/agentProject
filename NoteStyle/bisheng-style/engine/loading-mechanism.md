# 实例加载机制

## 概述

笔生skill采用**引擎+实例**架构：
- **引擎**（SKILL.md）：通用蒸馏框架、创作约束、质量保障
- **实例**（instances/[id]/）：特定作者的专属风格规则

## 匹配与加载流程

### Step 1: 意图识别

当用户触发笔生skill时，判断用户意图（对应 SKILL.md Phase 0 分类）：

| 用户意图 | 动作 | 对应Phase |
|---------|------|----------|
| 明确指定小说/作者 | 匹配注册表 → 加载对应实例 | Phase 0A |
| 模糊写作需求（只有类型） | Phase 0B需求诊断 → 推荐候选 | Phase 0B |
| "蒸馏新小说"/"分析XX风格" | 不加载实例，进入蒸馏流程 | Phase 0 → Phase 0.5 |
| "仿写XX风格"/"用XX风格写" | 匹配注册表 → 加载实例 → 创作模式 | Phase 0A → 创作模式 |

### Step 2: 实例匹配

读取 `instances/registry.yaml`，按以下优先级匹配：

1. **精确关键词匹配**：用户输入包含 `trigger_keywords` 中的任一关键词
2. **作者名匹配**：用户输入包含 `source_author`
3. **genre匹配**：用户输入的类型与实例genre一致

### Step 3: 加载策略

| 优先级 | 标记 | 加载时机 | 文件 |
|--------|------|---------|------|
| P0 | 始终加载 | skill激活时 | `manifest.yaml`, `rules/*.md` |
| P1 | 创作前加载 | 进入创作模式时 | `examples/` (如果有) |
| P2 | 按需加载 | 验证/对比时 | `validation/` (如果有) |

### Step 4: 规则合并

加载实例后，按以下原则合并引擎规则和实例规则：

1. **实例规则优先**：当实例规则与引擎通用规则冲突时，以实例规则为准
2. **引擎兜底**：实例未覆盖的维度，使用引擎通用规则
3. **不叠加**：同一维度不叠加引擎+实例两套规则，只取更具体的那个

## 新实例创建流程

1. 用户指定新小说 → 进入蒸馏模式
2. 蒸馏完成后，从 `engine/instance-template/` 复制模板
3. 填写蒸馏结果到对应文件
4. 在 `registry.yaml` 中注册新实例
5. 通过 Phase 4 验证后标记为 `status: active`

## 实例质量标准

| 状态 | 含义 |
|------|------|
| draft | 蒸馏中/未验证 |
| active | 通过验证，可用于创作 |
| deprecated | 已废弃/被替代 |
